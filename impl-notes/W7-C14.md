## Decisions and canon corrections

- OF-372: provider capability is not inferred from ordinary messaging. LINE and Messages for Business cannot advertise a made-up reaction-send API. Both expose an explicit unsupported vocabulary and the existing typed unsupported-capability error. The local iMessage bridge advertises the six classic tapback glyphs. In-app accepts non-empty strings of at most 64 Unicode scalars.
- OF-373: a successful connect tool return is not proof of delivery. Fresh pending/connected state is the proof. Ambiguous calls retain a durable local guard and cannot resend after restart.
- OF-374: Gmail is a provider for the existing `email` ChannelIdentity, not a second mailbox channel. Its send sink uses OF-327 `email.send`; Google `gmail.send` OAuth maps to `MailSend`. An OAuth token read binding alone cannot grant MailSend: the custody binding must explicitly carry `mail.send` too. Approval is specific to the identity and serialized message hash, never a reusable boolean.
- ARCH-0078 lists stale type bytes (105/110). This tree uses CODE_ARTIFACT=103 and BLOB_ARTIFACT=105. Do not renumber the registry from prose.
- ARCH-0075 names an older 604-case spreadsheet corpus; the pinned upstream release has 834. Its final unchanged-engine comparison uses native date/time serial values and meets the same-corpus LibreOffice threshold. The malformed LET case is a formula rejection, never a fabricated cached error. Native defaults cannot be selected from a smoke test.
- The Scope and reaction prerequisites described by the cluster are absent on this base: no unified Scope, no CONV-01 records listing/speaker door, and no CONV-05 record visibility function. See local context packets; these are not grounds to invent permissive substitutes.
