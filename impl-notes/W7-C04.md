## Decisions

- Code file documents use Loro in base mode, not only the optional sync transport.
  The transport's `sync` gate stays separate. This makes the file plane available
  to featureless engine callers as required by the contract.
- REAPI keys are SHA-256 digests of canonical protobuf Action messages. Existing
  blake3 snapshot identities map into a Directory descriptor. Hosts with a real
  REAPI CAS can supply the exact Directory digest. Cache rows use schema 2 and a
  new digest-key prefix; no deployed v1 rows exist.
- Account sharing is explicit. A host binds each member and an account artifact
  vault to the same immutable account identity. Both cache rows and their bytes
  live in that account vault. Artifact IDs are not reinterpreted in a member's
  entity namespace. `BuildCache::new` remains a local/trusted cache handle.
- Cache-keyed build/verify legs reserve an action before invoking the host. An
  uncertain execution is not automatically sent again. A completed cache row
  always wins. Returned provenance names the original producer.
- Working views use content-addressed codebase blobs and read-only hardlinks in
  a private host-owned directory. These are not a hostile-code sandbox. Foreign
  guests need the separate read-only microVM mount boundary. Writers submit
  operations rather than mutating these links. One view-set owns one LSP process.
- Consent wording and visible-file policy are consumer configuration in examples,
  authored by an agent asked in chat. Production code only renders/executes the
  supplied recipe. Host blast-radius numbers cannot be replaced by recipe input.
- Object-only GitWire writes pin objects but never create a served-ref intent.
  The origin protocol, not generic GitWire recovery, owns exported ref publication.

## Canon clarifications

The current spine says guests still propose whole files. The step-19 contract is
not permission to expose whole-byte canonical writes. Whole-file guest/git inputs
must be lowered at the door to spans against the guest's base document.

The old context pack called Loro sync-only and snapshots sha256. Those were code
observations, not the target architecture. Per-file documents are a base-mode
engine concern. New repository snapshots use blake3 and retain legacy recovery.

## Repository journal ownership

`repo.proposed_diff` and `repo.session` are engine-owned predicates. They record
review and execution facts, not arbitrary model memory. The review door writes
these records through the reserved claim owner path and retains the actor in
standard evidence and the session in subject/value. They intentionally do not
set `sess`, which routes envelope-bound session-bundle candidate writes. Public
claim APIs cannot rewrite these journal records. The normal queue still requires
immutable independent critic approval before any file effect.

## Validation-driven repairs

- Epoch receive-pack fixtures run Git from their own temporary repository, not the mirrored build checkout, which intentionally has no `.git`.
- Exact ingress verifies text and the captured frontier inside the writer transaction. A later-file refusal aborts every file edit for that pushed ref. Replay returns receipts without hiding newer edits.
- A stack sample of the existing 3 MiB streamed-push fixture identified redundant Loro history import and rich-text diff tracking. Equal-head/new-document writes now use their already-validated candidate directly. Existing stored snapshots are still verified, and genuine concurrent histories still merge. The same public fixture passed on the MacBook in 3.70 seconds; this is not a host-matched benchmark against the earlier Arch sample.
- Semantic comparison skips whitespace-only root syntax gaps instead of collapsing all whitespace. The regression preserves spaces inside `include!` string literals and ignores inter-definition blank lines.
- Cargo calls use the factory wrapper without a local-host override. The wrapper selected both MacBook and Arch slots during validation. Temporary test directories are worktree-relative (`TMPDIR={value="target",relative=true,force=true}` in a per-command config), so both hosts use a real existing path. No shared host configuration changed.
- Updated legacy integration expectations: automatic routing must select Firecracker or return `MicroVmBackendUnavailable`, even in debug builds. The development backend is available only by explicit construction. Routing fixtures pass in both sandbox-feature and featureless builds.

  WIT ABI. No such artifact is supplied by this worktree or the host. The local
  installed Rust target is native x86_64 only; no guest toolchain was installed.
- Step 3 needs the configured Firecracker/jailer binaries, pinned kernel/rootfs
  and protocol-v1 conformance guest component. The native fixture reads
  `ONEIRON_MICROVM_TEST_KERNEL`, `ONEIRON_MICROVM_TEST_ROOTFS` and
  `ONEIRON_MICROVM_TEST_COMPONENT`; none was configured. Neither Firecracker nor
  jailer was on PATH. `/dev/kvm` exists, but that alone is not a provisioned VMM
  stack. The ignored real-boot fixture must be run on a provisioned Linux host.

These are acceptance blockers, not a request to weaken tier selection or use the
non-isolating development backend. The engine fails closed without provisioned
native guests. Full-cluster DONE is not claimed.
