## Decisions

- Code file documents use Loro in base mode, not only the optional sync transport.
  The transport's `sync` gate stays separate. This makes the file plane available
  to featureless engine callers as required by the contract.
- REAPI keys are SHA-256 digests of canonical protobuf Action messages. Existing
  blake3 snapshot identities map into a Directory descriptor. Hosts with a real
  REAPI CAS can supply the exact Directory digest. Cache rows use schema 2 and a
  new digest-key prefix; no deployed v1 rows exist.
- Account sharing is explicit. A host binds each member and an account artifact
  vault to the same immutable account identity. Both cache rows and their bytes
  live in that account vault. Artifact IDs are not reinterpreted in a member's
  entity namespace. `BuildCache::new` remains a local/trusted cache handle.
- Cache-keyed build/verify legs reserve an action before invoking the host. An
  uncertain execution is not automatically sent again. A completed cache row
  always wins. Returned provenance names the original producer.
- Working views use content-addressed codebase blobs and read-only hardlinks in
  a private host-owned directory. These are not a hostile-code sandbox. Foreign
  guests need the separate read-only microVM mount boundary. Writers submit
  operations rather than mutating these links. One view-set owns one LSP process.
- Consent wording and visible-file policy are consumer configuration in examples,
  authored by an agent asked in chat. Production code only renders/executes the
  supplied recipe. Host blast-radius numbers cannot be replaced by recipe input.
- Object-only GitWire writes pin objects but never create a served-ref intent.
  The origin protocol, not generic GitWire recovery, owns exported ref publication.

## Canon clarifications

The current spine says guests still propose whole files. The step-19 contract is
not permission to expose whole-byte canonical writes. Whole-file guest/git inputs
must be lowered at the door to spans against the guest's base document.

The old context pack called Loro sync-only and snapshots sha256. Those were code
observations, not the target architecture. Per-file documents are a base-mode
engine concern. New repository snapshots use blake3 and retain legacy recovery.
