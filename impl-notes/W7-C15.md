## Per-step implementation and acceptance

### 1. ONE-2540 — persisted entity documents

Entity documents use `d:e:`, `sv:e:`, ordered `u:e:` updates, and `ssv:e:` after
shallow compaction. Recovery loads the snapshot before its updates, on demand
before issuing an edit handle. Weak registry entries retain Loro residents only
while an editor holds a handle; the live limit is 256. Serialized edits persist
before notification. No Observer B copies text over the ledger entity body.
The sweep recognizes document and queued-update carriers, fails closed on bad
keys, and does not compact a live editor.

Acceptance: `recovery_replays_snapshot_then_updates_after_kill_and_evicts_idle_docs`
and `document_sweep_defers_live_editor_then_erases_snapshot_updates_and_journal`.
Remaining: none.

### 2. ONE-2541 — one-socket document frames and v9

Document tag 11 and BATCH tag 12 have strict codecs, client/server dispatch,
per-connection selector admission, and entity-specific reactive notices.
Version 9 supports document traffic and either initial ledger mode; switching
ledger modes remains forbidden. Version 7 remains selector-only, version 6
retains its legacy lane, and version 8 is rejected.
`ds:e:` retains document subscriptions for reconnect. `qd:e:` journals local
updates in the edit transaction; only a covering ACK clears them.

Internal broadcast-gap notices are not wire frames. A local document relay
continues after overflow, local queries invalidate coarsely, and sockets with
document subscriptions reconnect to exchange their selectors and VVs again.

Acceptance: `document_and_batch_roundtrip_are_bounded_and_non_nesting`,
`document_and_batch_notices_invalidate_only_named_entity_queries`,
`document_batch_socket_admission_edit_ack_and_revocation`,
`offline_document_journal_survives_eviction_and_clears_only_on_covering_ack`, and
`document_relay_gap_requests_resync_and_preserves_later_edits`.
Remaining: none.

### 3. ONE-2542 — forward-only document export

The canonical ledger selector admits each document. First admission and a peer
behind either the persisted or live shallow floor receive `StateOnly(None)`,
not a delta. Admission floors bind the canonical selector encoding. Queued
server delivery rechecks admission; a raw notice is never an export fallback.
State-copy import preserves journaled local operations or refuses rather than
silently dropping them.

Acceptance: `admission_and_behind_shallow_peer_get_state_never_delta_and_future_edits_converge`
pins the Loro 1.13.9 stale-delta divergence and the convergent state-copy path.
Remaining: none.

### 4. ONE-2543 — remove loser BM25F postings atomically

The existing `apply_put` path already deindexes a replicated overwrite's old
text in the body transaction. The added regression observes the forward index,
lengths, postings, and winner body before that transaction commits.

Acceptance: `replicated_lww_overwrite_removes_loser_bm25f_in_the_write_transaction`.
Remaining: none.

### 5. ONE-2546 — federated confidence and audit

Federation applies a single 0.5 confidence multiplier and records the remote
value in `scope.federated_original_confidence`, replacing a forged audit field.
Both mirrored confidence fields of `edge.provenance` receive the same value;
otherwise its schema rejects the admitted row. Own-device confidence remains
unchanged.

Acceptance: `replay_tier_fork_scales_federated_confidence_once_and_audits_remote_value`
checks stored 0.375 versus remote/own-device 0.75, mirrored fields, audit value,
and repeat-import stability.
Remaining: none.

### 6. ONE-2547 — own-device/federated replay fork

Caller-bound `ImportTier` selects the raw-window and transaction-scoped
`put_replicated` admission paths. Both federated paths use the same claim gate.
Own-device replay and already-admitted crash replay remain trust-blind; recovery
does not compound the confidence multiplier.

Acceptance: the tier-fork test covers denied federation before source trust,
admitted member and direct guest replay, and unchanged own-device replay.
Remaining: none.

### 7. ONE-2548 — per-credential sync locality

The selector, egress scrub, reverse mirror, pending-mirror recovery, and replay
wall use the same predicate: custody-portable and not device-only. A stale
portable carrier cannot widen a locally narrowed credential. Forbidden or
malformed carriers force history-free export after removal. Generic secret
reads stay sealed, and credentials never own editable text documents.

Replay plans the name index before mutation and stages it with the body.
Duplicate live names are quarantined, existing ids cannot be renamed, and
revoked-name reclaim preserves the registration generation high-water rule.
This makes received credentials usable through name lookup and the bound value
door without leaving an index after a rejected write.

Acceptance: `custody_portable_dial_window_roundtrip_and_replay_wall` covers all
four locality cases and the bound read; `custody_replay_name_index_is_atomic_and_cannot_displace_live_name`
covers collisions, rename refusal, and rejection without index residue.
Remaining: none.

## Canon clarifications and scope

- ARCH-0044 app-tier tags existed at v8 in the base. This change completes the
  shared document/BATCH train at v9, rather than creating a second app protocol.
- BATCH is tag 12 followed by u32-BE lengths and complete tag-11 frames.
  Nesting is rejected; limits are 256 documents and 8 MiB for the complete frame.
  RPC/Sub limits continue to count payload bytes instead.
- `sv:e:` is absent while stale. The durable snapshot and ordered update log are
  the recovery authority. `m:u_seq:e:` allocates monotone u32-BE sequence numbers.
- ARCH-0043 requires down-weighting but gives no multiplier. This implementation
  pins 0.5 for both federation roles and keeps provenance confidence mirrors equal.
- Own-device custody replay retains settled generation and floor snapshots. It
  does not add a second trust/lifecycle gate; lease use checks the live local floor.
