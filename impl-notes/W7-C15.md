## Per-step status (implementation in progress; no acceptance claimed yet)

1. ONE-2540: entity documents use `d:e:`, `sv:e:`, `u:e:` and `ssv:e:`.
   Snapshot-then-update recovery runs on demand, before issuing a live edit handle.
   Weak residents evict immediately after the last editor drops; 256 live editors maximum.
   Serialized edit commits perform Observer A's durable append/notice duty; there is no Observer B.
   Added crash-process recovery and eviction tests. Compile/test validation remains.
2. ONE-2541: v9 document tag 11, BATCH tag 12, bounded non-nesting document frames.
   Server parse, client import, per-connection selector handling, and entity-specific reactive notices.
   Native clients now negotiate v9 for both planes. Window mode binding still prevents
   switching between full-window and selector-scoped ledger access. v6/v7 remain separate;
   v8 is rejected. `ds:e:` stores subscriptions; `qd:e:` journals local document frames
   atomically with their updates. ACKs clear the journal only with a covering peer VV.
   BATCH is limited to 256 documents and 8 MiB. Socket/test validation remains.
3. ONE-2542: the canonical ledger selector admits each text document. First admission and
   peers behind the persisted or live shallow floor get Loro `StateOnly(None)`, never deltas.
   Persisted admission floors bind the full selector encoding. Added pinned divergence test.
   The pinned Loro divergence and recovery tests pass. Sweep holds the registry lock
   through compaction; queued delivery re-runs entity selection rather than relaying raw
   notices. State-copy import preserves journaled local operations or refuses, never
   silently discards them. Final combined validation remains.
4. ONE-2543: existing `apply_put` already deindexes loser text in the overwrite transaction.
   Added an in-transaction stored-posting regression. Validation remains.
5. ONE-2546: federation halves confidence and records `scope.federated_original_confidence`.
   A peer's forged audit field is replaced. Canon requires down-weighting but gives no factor;
   this change pins 0.5 for both roles. Own-device values are unchanged. Validation remains.
6. ONE-2547: caller-bound `ImportTier` forks both raw window imports and transaction-scoped
   `put_replicated` via `sync::replay::replay_entity`. Both call the same per-entity admission
   function. Own-device and already-admitted crash replay remain trust-blind; federation
   is graded once. Direct and window replay tests pin the distinction. Validation remains.
7. ONE-2548: one portable-and-not-device-only predicate at selector, egress, reverse mirror,
   pending-mirror recovery, and replay wall. Generic secret read doors stay sealed.
   Excluded classes retain typed rejection/quarantine. Added window round-trip matrix;
   updated old seal fixtures to device-bound. Validation and stale-carrier review remain.

## Canon clarifications

- ARCH-0044 app-tier tags already exist at v8 in this base. This change completes the
  shared document/BATCH train at v9, rather than adding a second app-tier tag.
- BATCH encoding was unspecified. It is tag 12 followed by repeated u32-BE lengths and
  complete tag-11 frames. The shared 8 MiB total limit applies; nesting is rejected.
- `sv:e:` is absent while stale. Durable ordered updates are the recovery authority.
  `m:u_seq:e:` allocates monotone u32-BE update numbers in the same transaction.
- The text document owns editable text; no text write overwrites the ledger entity body.
