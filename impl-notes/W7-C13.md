## Step 18 recovery: actor-owned keyed long-term memory

The proposed `memory/key_value/` surface stores canonical CLAIM revisions,
not record type 107 or a raw KV side database. Identity includes the bound
actor ID, actor class, literal namespace segments and exact key. It is
explicitly worldless. There is no loose `world_ref: null => all` selector and
no new WorldScope declaration. The five `key_value_*` verbs are projected
through the shared backend, authenticated HTTP facade, both native clients,
and both SDKs. The root surface pin stays unchanged.

The recovery context packet was not an approved design. Its raw globally
actor-unscoped IDs, unguarded overwrite, structural payload storage, arbitrary
owner erasure and unchecked type-byte proposals were rejected. There is no
new registry type, raw storage endpoint, or MCP projection here.

The existing public `claim_upsert` is NOT composed naively: it supersedes an
existing active claim even when the replacement must park as proposed.
BaseStore cannot return success for that result. Keyed put therefore composes
the SAME gated ClaimCandidate/apply machinery and canonical supersession
primitive in one actor-verified transaction, with no proposed fallback. A
policy refusal aborts the whole transaction, including candidate, pending
consent, supersession and receipts. This is the same strict synchronous
choice already used for typed expression preferences. Source defaults to
`generated`, not `observed`; source trust and supersession protections stay
with the existing engine gate. Generated output cannot impersonate user
statements merely because a framework called put.

Delete composes the canonical retraction primitive after actor/class,
subject, envelope and exact scope are checked in the SAME writer snapshot.
It is not `safe_delete`, does not grant owner authority, and preserves
historical records. Reads use the existing ClaimOf index and fail loudly on
its work ceiling. Conflicting synced heads fail `INVALID_STATE` rather than
silently choosing a winner. Canonical demotion metadata does not turn exact
key access into ranked retrieval or expiry. No sync format changed.

Request IDs are domain-separated and actor/class/address bound. Full stored
identity, source and payload are checked before an identical replay returns.
A stale replay after replacement/retraction cannot resurrect a prior key.
The generic facade claim commit/upsert door rejects this typed predicate and
checks the STORED predicate inside its writer transaction, preventing a
caller from overwriting a keyed revision by disguising its incoming predicate.
This is an app-tier binding boundary, not a new ACL over the privileged raw
Vault/BatchBuilder systems surface. Those surfaces retain their existing
host-trust contract; this proposal does not widen them.

`oneiron-langgraph` subclasses the REAL `BaseStore` and implements
`batch`/`abatch`. It does not override the public convenience methods, import
checkpoint savers, open/rebind a handle, send HTTP or emulate exact get using
recall. The whole batch is preflight-validated, then dispatched in order.
Batches are not atomic; engine errors pass through and earlier successful
operations remain committed. Unsupported TTL, vector index fields, semantic
queries, wildcard namespace patterns and operator filters fail explicitly.
Search supports exact top-level field equality and exact namespace prefixes.
Namespace listing supports prefix/suffix, depth truncation, deduplication and
pagination. The README contains a runnable StateGraph sample.

The live SDK export censuses derive method names from the Rust catalog and
therefore cover the additional five methods automatically. The explicit
Rust expected catalog was updated. Added behavior tests cover engine gates,
actor/class isolation, disguised generic overwrite, replay/deletion,
namespace paging, demotion, authenticated HTTP scopes, native JS/Python,
installed remote parity and actual BaseStore operations. Wire CI includes
the new satellite and installed parity test, without publishing any artifact.

## Implementation

- Ports the actual C15 canonical `sync/documents` registry, storage, v9 document/batch codecs, manager API, socket handlers, client/connection plumbing, sweep and Doc reactive notices. Carries the necessary `BroadcastPayload` enum hunk in `server/core.rs`; preserves C13's memories-cursor field. C13's entity-level window invalidations stay intact.
- Does **not** port unrelated C15 custody-dial, federation confidence, ImportTier or replay changes. These are not dependencies of the document seam. Does not introduce a second protocol or retain `e:note:`. No compatibility migration is added.
- NOTE birth comes from the immutable ledger row and seeds deterministic Loro IDs. All editable NOTE state uses `d:e:` plus the canonical registry's key family. Snapshots include validated `pins` and persistent `authorship`, not a local-only pin sidecar. Reverse indexes are derived atomically on every admitted import/write.
- Adds `NOTE_OPS=4` and `NOTE_RECEIPT=5` inside C15 document framing. Commands contain an idempotency id and typed Edit/Cite operation, never a caller-authoritative actor field or raw Loro bytes. Upstream raw NOTE UPDATE/STATE and generic `EntityDocument::edit_text/import` refuse. A replicated ledger overwrite cannot change NOTE birth author or markdown at the batch put chokepoint.
- The real `/ws` upgrade authenticates an owner-grade transport credential, **not an actor**. Therefore NOTE REQUEST/NOTE_OPS additionally require existing MAC-verified `auth.bind`: core:read, core:write for mutation, registered principal, actor class and revocable jti. Selector member must equal that principal. Each stored subscription binds that selector/grant; every mutation rechecks its live grant, role and principal in the committing writer. A selector cannot name another writer.
- Core `Memory::admit_note_operation` receives the already verified host identity through the existing Memory binding. Its host contract is documented. No credential is recovered from a Loro message. The same LMDB writer rechecks actor binding, note author/owner, grant/pact/selector, token revocation, policy, erasure, pin sources and citation guards. Remote cross-author writes require an active human authority binding plus an Owner grant; the embedded unrooted-owner fallback is not accepted as remote authority.
- A cited-span edit uses the existing gated `ClaimCandidate`/`WriteEnvelope` path with Proposed approval, recording a real gate receipt **inside that same writer**. It does not call a wrapper that opens a nested writer. Free prose merges at the supplied base frontier and checks the resulting merged spans before persistence. The proposal leaves the NOTE unchanged.

## Explicit authority interface and limits

A subscribed NOTE has **one admission authority**. This is the safety boundary needed because raw C15 updates contain no authenticated actor.

- On a replica, `DocumentRegistry::submit_note` queues a semantic command in `qn:e:` and sends it on the existing socket. It does not speculatively mutate canonical text. Reconnect replays commands after the state exchange. The queue clears only after the received canonical frontier covers the Applied receipt (or a reviewed Proposed receipt arrives). Results persist in `nc:e:`.
- `SyncClientConfig.note_session = Some(NoteSyncSession::new(actor_slip))` explicitly opts into the configured server as NOTE authority. The client uses the current C13 MessagePack app envelope for auth.bind, not a parallel JSON RPC dialect. It accepts NOTE state only after the bind reply and for a persisted subscription. It requires WSS, or numeric loopback WS for same-host use. A remote cleartext endpoint is rejected. The existing owner upgrade credential is still separate.
- The client-only, crate-private canonical importer accepts admitted authority state, keeps pins and provenance, preserves existing local operations, and refuses citation drift. It is not callable by the upstream server handler. A subscribed replica refuses direct local Memory edits and cannot itself admit NOTE_OPS as a second authority. This prevents a replica that has not received every citing document from silently accepting a cross-citation edit.
- Facet-narrowed NOTE selectors currently fail closed. The canonical ledger admits NOTE as un-faceted, and transactional NOTE admission does not guess a one-hop facet closure from an older window snapshot. Empty-axis pact semantics remain fail-closed. World/band/grant checks and citation-source/claim disclosure checks run transactionally. Export withholds the entire NOTE if any retained citation would disclose a source or claim outside its selector. Coreference citations require their separate consent export door and are refused here.

Deploying NOTE_OPS-aware peers together and configuring actor slips/TLS is deployment work, not an in-repo engineering blocker.
- Birth ABI carries author_ref but no authenticated actor class. Deterministic birth provenance says `ledger` for that class; actual subsequent operations carry the credential's verified class. Local brief creation records its actual writer separately. Loro actor strings never grant permission.
