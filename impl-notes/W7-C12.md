# W7-C12 implementation notes

## 21 / ONE-2457 — byte-space v3.1 families

- Added the 15 ARCH-0058 family allocation ranges under `registry/families.rs`.
- Registry rows now declare family identity separately from byte and zone.
- `family_of` reads declared identity. `allocate_type_byte` chooses the lowest unoccupied family byte, then the zone overflow. System families have no overflow.
- `Vault::allocate_structural_kind` allocates under the same LMDB writer lock used to persist the registration. It preserves family identity across a spill and reopen.
- The explicit-slot `register_structural_kind` door remains for already assigned compiled-pack slots. Such rows have no inferred family. A byte number never fabricates a replication identity for them.
- Registry record v3 appends an optional family code. The ABI17 migration alone reads v2 records. The pre-v3 v1 decoder is removed.
- Runtime-installed PackByteMap is still not built. Bytes 128–247 remain rejected. Prefixes do not change.

## 22 / ONE-2458 — ABI17 → ABI18 re-key

- Replaced the v3 migration branch with the single v17→v18 branch. ABI16 and older fail closed. Existing-only open remains strict.
- The migration contains all 37 `byteMigrationV31` rows. Three rows are reserves with no registered substrate; they remain write-rejected.
- Every source is staged before any delete. Envelope byte 0, type-index leading byte, short-ID counter keys, and kind-registry rows change in one transaction. Registry survivors upgrade to record v3 in that transaction.
- Destination occupancy, malformed records, source/index disagreement and unloadable registry data abort before stamping ABI18. IDs, body bytes, timestamps, short-ID spellings and edge rows stay unchanged.
- Regenerated constant/prefix pins and the vendored canon fixture from docs commit `d0764449c4dd1ecbdc0bc6bde8408e2c1fb1f790`. Fixture payload BLAKE3: `9a7af385fde5243322903816041bd398901f543e72c2dca6c6ce516df8049847`.
- Updated receipt-family ABI pins, export-manifest pin and dedicated kind-constant assertions.

## 23 / ONE-2459 — classification/family replication

- Re-derived `SelectorRange` as classification scopes and explicit family scopes, not numerical ranges. Unknown, experimental and unclassified dynamic bytes have no replication identity.
- Pact ceilings and intersection account for classification scopes that cover multiple families. Family subsets never widen to all content.
- Sync selector export and federated admission now consult registry metadata. Maintenance write rejection and SECRET_CUSTODY's independent export prohibition remain.
- Replaced retired Companion/Productivity/CRM range callers with explicit families. Client retrieval defaults name People plus Productivity instead of the obsolete CRM interval.
- Selector and pact-scope schema versions advance to 2. Retired schema-1 payloads fail closed; persisted authorizations are not silently rewritten or widened. They need explicit reissue by the authority owner. The combined sync transport carries this schema change.

## 3–7 / OF-460 — rooms, DAGs, threads and audience

- Added the `conversation` module with pinned, forward-compatible room bodies, PERSON membership validation, kind defaults, filtered type-index pagination and same-transaction body/ledger updates. Generic body rewrites cannot change membership. Replica bodies cannot invent local history windows.
- Added parent/spawning/addressing/reply edge bytes 27–30, structural codecs and non-traversal policy. Raw graph writers cannot forge these edges. Parent/HEAD/canonical writes and thread metadata commit atomically; thread replies never advance HEAD. Legacy TURN backfill sorts by occurrence then id.
- Added membership windows including explicit history sharing, current-window grant/revoke, kick and rejoin. Presence is a bounded per-vault in-memory set, not a membership ledger or durable history.
- Added caller-authored scoped summary claims through `TxnBatchBuilder::claim_candidate`. The claim subject is the trunk. `covers` holds the exact resolved scope; `DerivedFrom` edges provide the evidence walk because the frozen edge vocabulary has no `Covers` kind.
- The single ScopedRead audience predicate now covers direct reads, text/vector candidates, edge peers, PPR visibility, context packs, timeline and short-id hydration. Ledger snapshots are keyed by room and membership revision so a reused read handle cannot retain pre-kick authority. Relationship-scoped claims use participant identity, not byte bands. OF-365 still runs as a separate conjunction.
- HTTP membership, records, thread/reply/summary, kind/external-id list filters, session mode and presence routes are added. The `as` record listing filter is not the authorization boundary. Context packs can name a room; its members, never its presence, define the audience.
- Added additive hex serde for EntityId with sentinel checks on decode. Added transaction-composable text indexing. Neither creates new root re-exports.

## Steps 12–20 — entity documents, forks and retained history

Integrated a shared EntityDoc (also used by ProposalTextArtifact), durable birth
actor/timestamp, per-op stamps, bounded LRU registry, ordered op persistence and
text-field migration. Anchored verbs enforce per-op actors and the 50-op limit.
Timeout output lands intact as an attributable rewrite fork. Durable fork rows
carry the proposal and causal base; settlement uses MERGE or SWITCH, with the
stale-base refusal only on SWITCH. Per-entity action grants are checked when the
proposal opens; authorized work lands and the remainder stays one review bundle.
Citation pins retain causal frontiers and quotes. Purge checks the owner proof
again inside its write transaction, clamps against all retention floors, exports
a Loro shallow snapshot and commits a receipt. Deleted anchors resolve DRIFTED
at their origin. Destructive deletion erases document/fork/history carriers;
archive does not. Read projections hydrate the document rather than pointer bytes.
All eleven focused fixtures passed on the MacBook (`.w7/doc-repair-test-2.log`). The later stale-rewrite MERGE extension passed in the repaired core run as well.
Canon: ARCH-0032, DEC-0006, ARCH-0035, ARCH-0073:35 and ARCH-0038. Citation versions
are causal frontiers, not invented scalar counters. A retained shallow boundary

## Step 1 — ephemeral partials

Integrated per-token, per-sentence, per-window and manual stream cadence,
originator-only/all-devices visibility and flush. Native EphemeralStore frames
use bounded lossy queues, never the durable sync queue or op log. The server
pumps local streams even without a SyncClient. Tests inspect durable substrates
before finality and exercise the actual server hub. All eight core stream fixtures and the server hub tests passed.

## Step 2 — idle/crash finality and continuation

Integrated bounded handles, generation-bound finalization, a configurable quiet
timeout (30 seconds by default), idle receipts, open-time crash recovery and
same-document continuation. Terminal writes preserve buffered output on refusal.
MESSAGE finality uses the existing witness ceiling and creates/updates EntityDoc
in the same transaction. Crash recovery discloses loss of the ephemeral tail:
without persisting partials, a hard crash can retain only the committed base (or
an empty first message). Canon ARCH-0002's crash wording should state that limit.
The streamState is joined from a receipt sidecar, not added to the canonical
MESSAGE envelope. Passing tests cover idle, reopen, bounds, continuation and races.

## Integration authority decisions

The existing replicated MESSAGE validator refuses every author bucket because
the wire has no verified source-actor proof. EntityDoc pointers do not bypass
that refusal. A pointer without its verified document is not accepted as an
ordinary text envelope. Ordinary local text edits retain the original text-index
field and run the existing secret scanner. Document migration is limited to text
fields, never actor, kind, membership or other policy fields. Runtime owner and
actor bindings are checked again inside document-write transactions.

sync,test-hooks --no-fail-fast` compiled both crates on the MacBook. The 2.3 GB
streamed object, full 4 KiB edit/re-upload, exact new chunk count, chunk GC,

query parameter flattening, and lost protocol-v8 app-tier negotiation. Repairs
are in the tree and are not yet accepted from that earlier run. Production
ABI review found no further stale byte predicates.

The macOS test environment must use a real TMPDIR. Cargo's host wrapper does
not forward TMPDIR. Subsequent runs use a worktree-local Cargo config file to
set a real test directory, not the symlinked `/var/folders` default. Stream
restart tests use the ordinary open door on every host, not the Linux-only
strict existing-vault preflight.

Published LFS chunk and manifest bodies are immutable through both ordinary
puts and entity-document migration. A focused regression checks refusal and
then resolves the unchanged object. Conversation unknown keys now preserve
MessagePack binary values (including existing `world_ref` fields), not only
JSON values. The wire keeps app-tier v8 available without chunk authority;
chunk selectors use v9 and owner full-window chunk transfer uses v10.

Legacy conversation DAGs now initialize on their first HEAD/canonical read,
not only on a later append. An explicit initialization marker also prevents a
non-advancing root from being mistaken for legacy trunk history on the next
append. The regression pins chronological backfill and an empty canonical
path after two non-advancing roots. MERGE accepts a retained rewrite fork using
its CRDT operations, including after concurrent live changes; only SWITCH has
the stale-base refusal. The timeout regression now accepts its durable full
output after a restart and verifies that the concurrent tail survives.

## ABI replay repair

The four-site canon table omits cached sync envelopes. A persisted v17 Loro
window could otherwise restore or export the old kind byte after the live rows
had moved to v18. The migration now marks those windows in the same transaction.
A sync-enabled vault upgrades their live envelopes before publishing a handle.
It preserves immutable CRDT history, imports pending updates first, and atomically
persists each upgraded snapshot before clearing its marker. Featureless opens
retain the markers for the next sync-enabled open. The new regression covers
snapshot-backed and pending-update-only windows plus a second open (PERSON byte
10 must not be mistaken for old ASSET_TEXT byte 10 and converted twice).
The regression passed on the corrected fixture, including both persisted forms and the second open.
