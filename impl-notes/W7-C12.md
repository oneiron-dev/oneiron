## 21 / ONE-2457 — byte-space v3.1 families

- Added the 15 ARCH-0058 family allocation ranges under `registry/families.rs`.
- Registry rows now declare family identity separately from byte and zone.
- `family_of` reads declared identity. `allocate_type_byte` chooses the lowest unoccupied family byte, then the zone overflow. System families have no overflow.
- `Vault::allocate_structural_kind` allocates under the same LMDB writer lock used to persist the registration. It preserves family identity across a spill and reopen.
- The explicit-slot `register_structural_kind` door remains for already assigned compiled-pack slots. Such rows have no inferred family. A byte number never fabricates a replication identity for them.
- Registry record v3 appends an optional family code. The ABI17 migration alone reads v2 records. The pre-v3 v1 decoder is removed.
- Runtime-installed PackByteMap is still not built. Bytes 128–247 remain rejected. Prefixes do not change.

## Integration authority decisions

The existing replicated MESSAGE validator refuses every author bucket because
the wire has no verified source-actor proof. EntityDoc pointers do not bypass
that refusal. A pointer without its verified document is not accepted as an
ordinary text envelope. Ordinary local text edits retain the original text-index
field and run the existing secret scanner. Document migration is limited to text
fields, never actor, kind, membership or other policy fields. Runtime owner and
actor bindings are checked again inside document-write transactions.

The four-site canon table omits cached sync envelopes. A persisted v17 Loro
window could otherwise restore or export the old kind byte after the live rows
had moved to v18. The migration now marks those windows in the same transaction.
A sync-enabled vault upgrades their live envelopes before publishing a handle.

persists each upgraded snapshot before clearing its marker. Featureless opens
retain the markers for the next sync-enabled open. The new regression covers
snapshot-backed and pending-update-only windows plus a second open (PERSON byte
10 must not be mistaken for old ASSET_TEXT byte 10 and converted twice).
