## Consolidation policy decisions

The v1 selection defaults are JSON data, loaded through a per-vault row override.
Soak defaults to zero to keep immediate consolidation available; the evidence
minimum defaults to one. Strength is the primary order, and the independent
`fan_in*(1+new_refs)` signal breaks strength ties. Weights are 0.7 Type-Prior
and 0.1 each for frequency, recency, diversity. The validator requires Type-Prior
weight to exceed the sum of the other weights. These are authored v1 rows, not
numbers handed to the judge.

ARCH-0003 §G.1 leaves per-predicate topic derivation unpinned. The current
implementation uses a structured value's `topic` field for the four named
set-cardinality rows, with whole-predicate question fallback when no explicit
topic exists. It never keys a question on its answer. All qualifiers remain in
the value key. Rules are operator-editable vault data. Prior-head evidence attachment requires exact actor-admitted DocumentVersion
read and write rights. There is no implicit all-vault scan. Multiple prior heads
for one question refuse rather than choosing an arbitrary winner. Scoped sink
consumers must persist the opaque handoff through promote_scoped_consolidation;
the default custom-sink method refuses instead of dropping its transaction pins.


## Private-memory implementation decisions

1. Diary is `NOTE { kind: "diary" }`. `Memory::author_note(NoteWriteEnvelope)` is the general typed NOTE writer. Existing `author_take` delegates to it. The engine stamps `author_ref`, writes the mandatory AuthoredBy edge, and binds diary About to the same actor. Diary cannot use a public subject/claim scope or name another owner. Raw NOTE writers remain refused.
2. NOTE pre-GA ABI changes from exactly three keys to exactly four. `source_revision_ref` is REQUIRED and exactly 16 MessagePack binary bytes. It is an opaque revision identity, not a dereferenceable entity id. All takes also carry it. Existing author_take convenience calls mint one; typed callers supply the source revision. No old decoder/migration was added, per prerelease rules.
3. The shared NOTE admission predicate decodes fail-closed. Ordinary retrieval has no private-note authority, including when the caller is the diary owner. Direct actor-keyed reads can include the owner's diary. Ordinary lexical search, direct vector output, pipeline status gate, pack hydration, edge expansion, hydrated edge lists and ordinary PPR seeds/transit exclude diary and malformed NOTE rows. Scoped raw get/parts, short-id hydration, graph edges, timeline, result filtering and pack filtering enforce the author key. The facade's get/hydrate/neighbors apply the same NOTE rule. NOTE suppression also triggers orphan-neighbor trimming without changing the claims-only suppression metric.
4. Owner-keyed `ScopedRead` diary reads require the exact actor EntityId and a class-valid existing actor row, not a display name or a classless key. `ScopedReadActorKey::with_actor_class(owner.to_hex(), "human"|"agent"|"system")` is the existing typed host binding. No broad scoped grant can override diary ownership.
5. Scratchpad is a durable Context Board plugin block. No scratchpad NOTE kind, private_notes module, diary endpoint or standalone scratchpad endpoint exists. New generic board state doors are `Memory::put_board_block`, `Memory::board_blocks`, and `Memory::board_block_snapshot`. Types are re-exported from `context_board`, not the crate root. `BoardBlockWriteEnvelope` binds `ActorPrivate { owner_ref }`; its owner must be the facade actor. Each append stores a fresh block id, author, required source revision and markdown in a strict version-1 vault_meta row. Typed snapshot rows flow into the existing plugin renderer, including its quoted-leaf and budget controls.
6. Board blocks require an ALREADY admitted plugin section with `state_family = { family: "scratchpad", version: 1 }` and `authority_lane = "actor.private"`. No section is auto-installed or consent-bypassed. The writer rereads the actual approved/live install CLAIM and exact Active skill in the write transaction. Reads reread the same facts and actor binding in one read snapshot. A stale cached registry cannot authorize writes or reads after install retraction or skill drift. Host section resolvers must recognize those implemented state-family/authority references. Names and prompt content remain host configuration.
7. Scratchpad state is append-only revision history. The bounded block read returns the first requested revisions in block-id order. It is vault-local metadata, not an indexed entity and not an ephemeral board-stream subscription. The ordinary entity-row export enumerator does not enumerate this local metadata.

## Integrated boundaries

- UI and agents use one named action registry and gated executor. A durable action
  reservation blocks duplicate effects. A crash after reservation is uncertain and
  requires reconciliation, not an automatic second dispatch.
- Connector qualification runs against a host transport/oracle adapter. Tool output
  cannot grade itself. OAuth binds vault, actor, issuer and response state before
  redemption. CIMD uses an operator-configured HTTPS origin and pins
  `draft-ietf-oauth-client-id-metadata-document-00`; it declares neither sampling
  nor roots.
- Header consent is a separate conjunctive grant class. The prepared descriptor owns
  canonical frozen headers, arguments, sensitivity and preview/mutation intent all
  the way through binding, ledger and recovery. Explicit mutation does not grant
  authority. Destructive preview refuses unless the schema declares boolean
  `dry_run`; an ignored extra argument is not a safety guarantee.
- One vault-owned Dreamer identity stamps execution, promotion, optimization and
  maintenance facets. It receives no implicit ceiling. Independent agent dispatch
  keeps its own principal. Curator/eval/digest jobs use the shared proposal gate.
  Config-eval proposals and baseline updates co-commit. Digest identities cover
  rendered text as well as typed groups. Curator findings never delete targets.
- Representation consumes scoped text CLAIMs and actual owner-authored voice
  samples. It pins exact body revisions, quotes and citations, then stores immutable
  draft bytes. An exact owner bundle approval is required to arm OF-327; generic
  inbox approval cannot arm delivery. Dispatch rechecks sources and bindings before
  the existing consent, window, budget and replay doors. Citation checks prove the
  quote/ref/revision, not semantic entailment. The model is a host-supplied bounded
  planner, not a built-in persona. Existing transport concurrency boundaries remain.
- Branch Scope is an additional resource limit, not actor read permission. Actual
  queued parent lineage, exact document versions, ordered TURN slices and real
  bucket/output/signals/gap keys constrain consolidation. Missing rights refuse.
  Project is a caller-defined exact source slice; relationship-constrained output
  cannot erase that axis. Stored graph/embedding inputs remain active and filtered.
  Global gap maintenance refuses an explicit branch scope. Root entries without a
  queued scope admit live versions; explicit scopes retain their pins across runs.
- Agent dispatch persists/attenuates Scope before queue/fork writes. Its context
  descriptors do not return resolved bytes. There is no in-engine agent.dispatch
  executor: hosts re-resolve through their existing actor-bound ScopedRead doors.
  Final data-flow review found no additional dispatch read bypass.
- Standing caches are disposable, node-local projections. POST
  `/v1/core/context-board` resolves the authenticated agent/world handle, reserves
  its floor before retrieval, clamps remaining context and checks the complete
  serialized response budget. Omitted controls, classless bypass and lower floors
  refuse. Eviction records identify removed claims without deleting them.
- Connector event ingestion preserves the typed context through the actual
  `dreamer.connector_event` attempt and driver callback. A host handles the agent
  response. Matches, wake decisions and budget debits co-commit; replay cannot
  double-charge. Suspended/depleted subscriptions do not wake.
- OSV sends dependency coordinates only. Skill import and advisory scan-ledger
  receipt co-commit, so activation cannot pass between them. npm/PyPI readers and
  the typed coordinate door share the existing effect dispatcher; clean responses
  produce no advisory and findings do not become a separate blocking policy.
