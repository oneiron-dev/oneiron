## Integration decisions and review

- PROJECT is registered through the existing compiled-pack registration door at byte 107 / prefix `pj` / pack `oneiron.project`. The static canon byte snapshot is not hand-edited. Canon needs to record this allocation. Root identity is minted once per vault; the initial leader is its existing `sys.team_lead` definition. The owner can replace the root roster and leader without reseeding.
- Home-room ids are derived from project ids. Project writes, including raw batch writes, project membership into existing CONVERSATION rows. Room membership grants no additional claims scope. ChangeLog rows are local derived projection evidence, not a second replicated authority source.
- Scope references and member references round-trip as canonical ids. Project ancestry must resolve and be acyclic. Optional goal/budget/member rows can be filled in after the root is seeded.
- Task-review finding: deleted TASK symbol holds now clear at the common deindex door. The suggestion to recreate a deleted wave slot was rejected: retry must not undo an owner's deletion by minting a replacement. A deleted planned task makes that plan fail closed.
- Task-review quota finding was resolved against the newer OF-520 contract, not by adding a rate refusal. Every new task is counted; plan retries do not recount reused tasks.
- Linear inbound fields update the mirror projection and title, never the engine's execution spec, terminal result, or assignee routing. Scheduler readiness uses authoritative execution state.
