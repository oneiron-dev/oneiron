- The engine remains consumer-neutral. Cloud control-plane changes cannot be placed in this Rust engine as product-specific Convex files.

- MAIL-11 DKIM crypto is blocked on a restricted Track-B annex. No replacement cryptography is invented.
- ONE-2343 is reachable on `w7/W7-TRIAL`, but is not an ancestor of this branch. No other branch is changed. C9 is reused for step-only waits; the ask-local outcome binding is retained pending integration.
- New APIs live under their owning modules. No new crate-root export is required for the work so far.

## Integration decisions and review

- PROJECT is registered through the existing compiled-pack registration door with prefix `pj` / pack `oneiron.project`. The allocator selects a free compiled-product slot (107 on a fresh vault, not a universal type byte). Validators and projections resolve the persisted pack binding. Existing CRM slots are never hijacked. The static canon byte snapshot is not hand-edited. Root identity is minted once per vault; the initial leader is its existing `sys.team_lead` definition. The owner can replace the root roster and leader without reseeding.
- Home-room ids are derived from project ids. Project writes, including raw batch writes, project membership into existing CONVERSATION rows. Room membership grants no additional claims scope. ChangeLog rows are local derived projection evidence, not a second replicated authority source.
- Scope references and member references round-trip as canonical ids. Project ancestry must resolve and be acyclic. Optional goal/budget/member rows can be filled in after the root is seeded.
- Task-review finding: deleted TASK symbol holds now clear at the common deindex door. The suggestion to recreate a deleted wave slot was rejected: retry must not undo an owner's deletion by minting a replacement. A deleted planned task makes that plan fail closed.
- Task-review quota finding was resolved against the newer OF-520 contract, not by adding a rate refusal. Every new task is counted; plan retries do not recount reused tasks.
- Linear inbound fields update the mirror projection and title, never the engine's execution spec, terminal result, or assignee routing. Scheduler readiness uses authoritative execution state.

## Current integration evidence and limitations

- An earlier scoped run compiled core and ran `blob_artifact::esign`, `task_verb::`, `llm::step::`, native mail and outbound tests: **286 passed, 1 failed, 1 ignored**. The failure was PDF object-stream admission: lopdf filters both the stream and its xref entry. Admission now compares the parsed objects to the *original* xref set. Superseded by the green e-sign tests in the focused 77-pass run.
- Public signing capabilities are 256-bit values stored only as hashes. The browser consumes a fragment token and clears the fragment; JSON POST carries it, with no session/cookies, no-store and no-referrer responses. Download uses an immutable pinned artifact version, not a mutable head. Host-supplied forwarded IP headers are not trusted as audit identity.
- Native PDF preparation deliberately supports a bounded static profile. See `impl-notes/W7-C03-render.md`; it is not evidence that arbitrary upload, HTML templates or all fonts work.
- Task first-answer settlement is node-local serialized vault authority. Step-only C9 traps never park or resume the queue attempt. An external SDK step can use a private, actor-bound detached C9 context, without inventing an engine run.
- Engine SDK verb constants now generate the MCP tasks/rooms tools. Existing non-MCP HTTP/NAPI/TypeScript surfaces are hand-written; the canon's all-wire generation rule is not implemented repository-wide by this change.
- Canon correction: ARCH-0064 needs to state the production PDF rendering profile or supply the general renderer; ARCH-0063/CID-3 must distinguish engine admission from cloud fulfillment. ARCH-0006a's single generated SDK table remains an architectural target rather than current repository fact.

- Public HTTP/generated MCP validation: `cargo test -p oneiron-server --lib -- mcp::tests api::esign::tests --test-threads=2`: **69 passed**, using the factory MacBook target and worktree-relative real TMPDIR.
- The follow-up renderer refusal was traced to the fixture writer silently discarding ObjStm objects; the fixture now patches a same-length placeholder to carry a real object stream without changing xref offsets.
- Seal output and signature uploads now use a vault-local MACHINE actor (created transactionally on first use). Artifact ids are not provenance actors. This adds no class-wide policy grant; generated versions keep their existing Proposed floor.
- C9 step-only transitions clamp their time to the authenticated predecessor's time. A stale step context cannot create an inverted supersession range after a newer signal.
- Public PDF-first access carries the real peer IP and UA into Viewed. Missing peer transport fails closed. The managed listener must supply peer information before hosting signing pages. Forwarding headers alone are never legal audit evidence.
- Signature images have a 64 MiB aggregate stored-byte budget per document and seal preparation has a separate 64 MiB decoded raster budget. Exact image retries do not spend twice.
- Certificate QR links accept the shipped page's 64-hex fragment bearer without leaking it in an HTTP path or query. Other fragments remain rejected.

- Full crate testing exposed numeric-slot hijacking: the old PROJECT check interpreted every dynamic byte 107 as a project, even on an unseeded CRM vault. This is fixed at the common put validator and projector using the live pack binding; a CRM-before-project reopen fixture covers allocation and preserved type identities. Campaign registration fixtures now select free *live* slots and compare the registry before/after a refused operation instead of assuming an empty registry.
