# W8-T06 implementation notes

Canon: read-only docs mirror `site/src/pages/oneiron/agents/oneiron-arch-0028-mcp-external-agent-surface-v1.astro`, especially the SDK projection and complete tools/list rule (lines 213–217, 314–316, 577–590). The in-code schema/decoder parity promise is in `crates/oneiron-server/src/mcp/endpoint_schema.rs`.

Decisions: Treat nullable integer schemas as integer positions during raw and parsed normalization, but leave free-form untyped values alone. Preserve typed nullable string field types when merging envelope constraints, while keeping `frame_epoch` integer-only because its custom decoder rejects explicit null, and use `allOf` for boolean/non-object typed schemas when the envelope adds constraints (empty envelopes keep the original schema). An unavailable root schema (`false`) on a `$` projection refuses that MCP projection instead of publishing a schema that denies all calls. Cache typed schemas once in a `LazyLock` map; only clone where an owned projection is needed. The cache holds immutable compiled type metadata, not vault or actor state, and avoids regenerating every schema on each tool listing. The process-global ratchet remains at its pinned 34.

Canon clarification: ARCH-0028 says a signature that cannot generate a schema is a facade bug, not a reason to curate the verb table. It does not spell out nullable integer rewriting, nullable defaults, integer-envelope precedence, boolean-schema constraint merging, or the distinction between `false` and missing root schema. The canon should explicitly state that advertised wire schemas and decoder admission agree on these payloads, and describe the `$`-row no-schema case as an error to repair at the facade rather than a curated omission. The ticket's RISK 20 statement could not be verified in the read-only mirror; do not treat it as canon.
