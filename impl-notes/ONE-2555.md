# ONE-2555: script-adapter execution boundary

The 2026-09-25 amendment to ARCH-0053 §7 fixes the carrier: reuse code mode. There is no new subprocess-or-WASM choice here. An imported script is **foreign** code, so it must execute in the existing propose-only Firecracker/`oneiron-guest` code-mode lane with the pinned foreign QuickJS component. The in-process Wasmtime runtime explicitly refuses foreign tier; the dev process backend is not isolation. Missing configured Firecracker, pins or key grants means refusal, never a fallback to host JavaScript.

The source is the immutable, hash-pinned installed `PackSource`, not a caller-supplied path or program. Only files in its declared source tree are copied into the guest's fresh workspace. The adapter path must name one of those files. Host-only connector-key metadata binds the requested grant to an active key and an opaque credential handle. Material stays with the egress proxy/credential resolver, never in the pack, guest, output, receipt, or event. Each guest call remains limited by that key and its destination allowlist. There is no ambient filesystem or network authority.

Guest outputs are data, not a direct vault mutation: validate a bounded, typed result before handing inbound records to the existing SurfaceEvent router, outbound *intents* to the ordinary channel-verb admission path (never inline sends), and matching connector events to the OF-218 subscription/wake door. Do not route output after a guest trap, nonzero exit, unexpected proposal, revoked key or preflight validation failure. Once validated, separate durable inbound and connector-wake doors are independently idempotent; they are not one cross-system transaction. A code-running install step uses this same code-run boundary under the object's grant. The host-supplied code auto-install switch defaults off; that path returns Candidate with the *same* immutable `PackInstallAsk` permission-card data, even if a manual install approval exists. A host may opt in only after its provisioned Firecracker sandbox tests pass. The on path still uses the existing qualification, source/rules checks, and approve-once install door: the current pack install has no faithful undo (`UndoFidelity::None`), so the consent fit ladder asks rather than silently installing this irreversible effect. Neither switch value grants the requested slate or bypasses advisory/re-consent. Code-running install steps must be separate code-mode sandbox runs under the object's grant, not code executed by `prepare_pack_install` or by the metadata transaction.

This note records the amended carrier choice, not a claim that unprivileged local protocol tests prove a real Firecracker boot. Production acceptance needs a pinned host profile and the real-boot script fixture as well as local protocol/featureless tests.
