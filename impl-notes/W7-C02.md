## Trust and implementation decisions

- SELF-GRANT is local author proof, not a copied actor/source field. Imported or
  raw native rows do not become a caller's authored memory by assertion. Native
  Vault/projector doors remain trusted; app-facing edits use the Memory wrappers.
- Admin authority requires authenticated root ownership or exact named delegation.
  PERSON type, job title, review participation and an Auto descriptor grant none.
  Conflict packets keep refs/digests, not an undeletable second plaintext archive.
- A workflow is inert saved data, not a code-mode language. Only leaf AGENT_DEF
  actors execute. Host external effects still need their normal idempotency key;
  callback recovery is not exactly-once external I/O. Cancellation uses existing
  descendant controls rather than cancelling only the paused wrapper.
- Ask answers are evidence, never consent. No-live-route is a queued status, not a
  blocked run. Authority facts bind actual group membership and answer lineage.
- Hub scoring runs outside the LMDB writer lock, then rechecks exact bytes,
  baseline, policy and publisher authority before commit. No source file grants
  activation. Changed Active hub revisions now return a deduplicated held-out
  proposal; the synchronous unscored sync door cannot overwrite admitted bytes.
  Candidate narrowing and the owner's governance tier still survive sync.
- Shared merge accepts only submitted bytes. It does not open the sender's vault,
  install a process-global scorer or invent federation membership.
- OF-335 does not specify weights/defaults. Equal normalized weights and an
  explicitly missing neutral 0.5 are implementation choices, not clinical labels.
- All new public types stay under owning modules. The 701-name crate-root pin is
  unchanged. Unpublished codecs change in place; no compatibility-only decoder.

## Export limits and canon corrections

The source-folder path is real for persisted packages, not a claim that a
metadata row contains missing files. SKILL.md/scripts retain exact UTF-8 bytes,
file SHA-256 and canonical tree hash. Agent folders derive PACK.md, actual
instructions, inert policy, stored skill hash refs and selected ordinary claims.

A local birth/fork captures the real parent tree hash in the same transaction.
Export-time lookup of a subsequently edited parent is not historical proof.
Older/sync-born rows without this binding have an explicit omission. Imported
bindings remain untrusted lineage and cannot enable a definition.

Remaining source/restore boundaries:

1. The base has no predicate-pack source catalog/PackByteMap storage. Predicate
   names cannot reconstruct source folders.
2. Compiled ingest adapter registrations are descriptors, not stored connector
   packs. OF-519's connector-pack source/admission foundation is not present.
3. Older/authored/distilled skills without persisted files get
   `skill_source_unavailable`; descriptions are not invented SKILL.md files.
4. Historical/sync-born fork hashes cannot be recovered honestly. Replication of
   the new local birth binding is not implemented.
5. Other maintenance families, reserved claims, witness/owned rows and provenanced
   edges need domain-owned restore adapters. No generic reserved-write/replay/Auto
   bypass is supplied. Closed archive-only hub provenance/configuration/scan rows
   are not restored as authority; local scanning runs over the imported bytes.
6. Redacted/binary source files have no asserted clear-file hash. Partial trees
   cannot import as complete packages. Agent knowledge folders are private owner
   archives, not a permissionless hub publication surface.

ARCH-0027 describes intended pack foundations, not the base's former metadata-only

## Source-preserving new skill births

- Conversation conversion now persists the exact `RefinedSkill.files` tree in the same
  transaction as its Candidate record. The canonical hash and `convert-<first16hash>`
  version are still computed from those unmodified files. An exact duplicate still
  returns the existing holder before interpreting a new package.
- `SkillPackageFormat::{Folder, Native}` records source syntax, not provenance or trust.
  Folder requires scalar name/description/version. Native permits absent or partial
  frontmatter and keeps native identity/description/version separate. Capability
  declarations are still parsed from actual source. Native storage rejects envelope
  capabilities that differ from those declarations. No string version is inserted into
  the bytes that generated it.
- A source-bearing fork re-reads the parent and files under its write transaction. It
  copies all companion files, edits SKILL.md name/version, re-declares the stored
  capability sets, recomputes the canonical hash and persists the new package with its
  record and DerivedFrom edge. An already-resident resulting hash is refused before
  writing a second holder. The original body after frontmatter remains exact.
  Existing non-identity frontmatter lines survive. A historical parent without stored
  source still produces an explicitly source-unavailable metadata fork. No description
  is passed off as recovered source.
- Whole-vault bundles carry source_format paired with source_tree. Validators enforce
  pairing, tree hash, syntax and native-field agreement where the syntax promises it.
  Archive reimport parses actual source, forces Imported/Proposed/Candidate via the
  existing importer, runs the native scanner and keeps the activation guard unchanged.
  All serializer credential nulling, reserved-row policy and replica gates are unchanged.
- The unshipped v1 local package codec now stores a one-byte format tag. No compatibility
  decoder is added for development-only bytes. The root export pin is unchanged.

### Optimizer audit boundary

`SkillEditDraft::Edit` (`skill_optimize/brief.rs`) accepts only `desc` and `rationale`.
`run_skill_optimize_bound` (`skill_optimize/job.rs`) stores that exact authored text in
`SkillRecord.desc`. It receives no file tree and no replacement instruction-file payload.
The held-out replay path also scores `desc`. Thus there is no discarded file argument
analogous to conversion. Materializing `SKILL.md` from this metadata would invent a
source representation; copying a parent's instruction files would advertise the old
instructions as the new draft. This draft does neither. A real optimizer source-edit
contract needs a source-aware author brief, edit payload and scorer binding together.
Its metadata-only proposals remain `SkillSourceUnavailable`, as do historical missing
packages. This is an explicit substrate boundary, not synthesized recovery.

### Canon correction

`skill_convert/types.rs` formerly said the host retains source and the engine stores only
record+hash. That comment is now wrong for Step 1 and is corrected here. The canon should
say accepted converted sources are locally persisted atomically, while native metadata
is an envelope over exact bytes, not normalized frontmatter. Fork source identity is a
new hash of copied-and-reidentified bytes, never a copy of the parent hash. Archive source
format is untrusted syntax metadata and carries no consent, approval, scanner verdict or
activation authority.

existing typed hub-sync transaction remains allowed to replace both halves.

all three ordinary doors. A general owner/optimizer source-edit producer is still
not supplied by the metadata-only draft API; no file edit is fabricated from it.
