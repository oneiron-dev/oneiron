Findings remain private artifacts; verdicts and outcomes are claims with session provenance. The node-local projector binds emitted claims to private content digests; raw/synced claims are not calibration events. - ARCH-0053 manifest revision choice: tier-1 index uses the dependency-list content hash; actor claims use the encoded body hash. Neither uses an invented revision counter. Skill pulls retain the stored semantic version. The engine exposes attempt-bound load doors because ordinary repository reads have no attempt identity.

Unsupported reserved/witness families refuse atomically pending their typed adapters; this is not a full owner-restore format.

- The ARCH-0027 sentence saying TOON still calls `toon_format::encode_default` is stale. This base already has the native tabular encoder.

# W7-C02 saved workflow dispatch — integration notes

## Decisions

- `AgentDispatchTarget::Workflow(id)` loads the stored byte-18 `WorkflowDefinition`. Its ordered steps remain inert data.
- A workflow has an `agent.workflow` queue wrapper, not a fake AGENT_DEF. Only real leaf definitions receive Agent-class write actors. `agent_dispatch_actor` now returns `Result<WriteActor>` to reject manually constructed workflow-as-agent inputs.
- Admission freezes every real leaf in one writer transaction. A later fork-registration failure aborts earlier forks, the wrapper, and every queue write.
- The wrapper stays paused, so ordinary workers cannot claim it. Only the active leaf exists as queued work. `advance_workflow` releases a successor only after the active retry tip is Completed and has a write-once result ref. Wrapper settlement, cursor movement, successor enqueue, and aggregate report writes are transactional.
- `run_workflow_step` is a typed host callback door. It leases the current leaf, resolves live context, calls host code, and settles its result. A concurrent caller sees Waiting. Completed callbacks are not replayed.
- Authority traversal crosses only a registered inert wrapper to its real parent. A parented workflow requires actual agent lineage. Direct spawning under a wrapper is refused instead of taking the missing-parent compatibility fallback. Context ancestor folds skip the wrapper without dropping the real parent's live descriptor or approved widening. Structural depth is charged once per real leaf, not once per container.
- Dedupe is retained in vault-local metadata after queue completion. The same workflow intent returns the existing report and cannot rerun completed steps merely because generic advisory dedupe retired.
- Each result records ordinal, requested definition, actual dispatched/attenuated definition, settled attempt, and result ref. `workflow_status` reads that durable report. Wrapper result refs use `workflow-report:<root-attempt-hex>` and resolve through this typed door.
- No process-global state, new prompt language, or fake actor identity exists.

## Boundaries and exact remaining gaps

- Ordinary agent propose-widen remains on its existing path, including descendants of workflow leaves. The approved-board lookup crosses an inert wrapper to the real board. A *workflow-level* widening request is refused by normal context validation. It does not produce a proposal for one leaf, because approving that would launch only one leaf and lose the workflow intent. Supporting whole-workflow widening requires storing the workflow intent/frozen revision in WidenIntent and landing atomic workflow admission in approve_context_widen. This draft does not pretend that gap is closed.
- Hosts must adopt `run_workflow_step` or call `advance_workflow` after normal leaf settlement and during recovery. No server scheduler route is changed. The core typed runner is complete; automatic host scheduling is outside this patch.
- A callback that performs an external effect and crashes before durable result attachment can execute again under normal lease recovery. The host must use its effect idempotency door. No exactly-once external-I/O claim is made.
- The wrapper's queue status is Paused while orchestration is active. Its children show real progress. No new queue lifecycle state is introduced.
- Generic cancellation of only the wrapper does not cascade to an already-admitted child. The typed runner stops on a non-paused wrapper; hosts using generic workers must use existing descendant cancellation controls as well.
- A stopped/failed leaf terminates its wrapper without releasing later steps. Automatic workflow-level retries are not invented. Leaf retry chains already minted through AttemptQueue are followed and retain correct provenance.
- Frozen composition is preserved at release. Live target revocation, live parent ceiling, depth and context are rechecked before each release. A narrowed live authority can mint another restricted actual leaf target.

## Canon correction

Any description saying that saved ordered workflows are implemented by enqueueing all steps in order is insufficient. Queue order is not execution order when workers run concurrently. The contract should name durable successor release after a lease-fenced Completed result, a typed result report, and an inert authority-transparent wrapper.

# W7-C02 preference learning — implementation note addition

## Steps 12–14

- Untouched approvals from owner-bound inbox intake persist immutable decision rows in the same consent transaction. Repeated identical semantic approvals produce a Proposed `preference.affirmed` claim with reviewed content and receipt evidence. They do not fabricate a skill win: a gate receipt has no skill manifest. The existing optimizer healthy keep/no-op path remains byte-identical.
- `CompilationTarget::{Ban,StyleRule,CharterLine,BriefUpdate,Fallback}` is an explicit intake decision. No `never`/`always` language heuristics were added. All compiled outputs remain reviewable proposals. Fallback keeps lexical phrasing versus skill-edit classification. Untyped rejections do not invent a rule.
- Style proposals use `preference.style_rule`, cite `companion.expression.style` as their target, and reuse OF-332's token validator. They do not directly call `set_expression_preference`: OF-332 is Auto-or-refuse and cannot park a Proposed head without violating its supersession contract. Installing a style still uses that existing typed, gated door after explicit owner action. No charter, ban, or brief authority is silently installed by mining.
- Each decision names the human principal supplied by the authenticated host. Intake checks `verify_owner_write_actor_in_txn` under the write transaction. The generator actor and session id are never used as the principal. The measured-artifact lane has an immutable `bind_amendment_preference_principal` intake, also owner-checked. The host must call this when taking that owner's explicit decision; it is not a migration or an inference job.
- `scope.principal` is a validated 16-byte entity id. Unknown legacy audiences are audit-only, never global preference grants. Common scoped reads, active-preference reads, miner recurrence, and optimizer personal substitution evidence honor the audience. Learned preference consent through the inbox requires that same principal and cannot change its audience through an amendment.
- A single durable-class half-life (365 days), at a 0.5 influence threshold, applies to teaching receipts and learned-preference reads. Future-dated evidence cannot influence. The miner counts only current evidence before reaching K. The optimizer checks every teaching receipt, the proposal's age, the explicit principal, and the pre-existing DEV partition. No stored evidence is deleted by decay.
- Unbound optimizer jobs have no principal and therefore read no personal substitution evidence. `optimize_brief_for_principal_at` and `run_skill_optimize_as` supply the explicit owner audience. Genuine attempt reliability/defect/discovery evidence remains governed by the existing attribution and DEV partition laws, not relabelled as personal taste. Authenticated proposals carry `preferencePrincipal` in their provenance.
