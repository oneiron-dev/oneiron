### Criticality decisions

- `ContextEntity.critical` is a manifest-derived predicate-class projection, not stored per-claim guessing. Hydration resolves one policy snapshot after D19. Serialization never expands the visible set or the world/facet partition.
- `criticality(bool)` on query/pack builders selects a tier only. It cannot promote a normal predicate.
- The old serializer exempted a hardcoded predicate list from item and section budgets. That contradicts ARCH-0003 and is removed. Tests asserting that exemption are replaced by hard-limit tests.
- A positive serialized budget smaller than the format's empty scaffolding emits `{}` for JSON or empty bytes for text formats. Exact token stats and the warning remain available on the typed stats API; no unlimited envelope exception remains.
- The factory cargo dispatcher selected Arch slot 1/2 for the latest run. It used this worktree's target and the existing job limit; no machine or tool was installed or changed.

### Conflict persistence and source ranking draft (steps18–20)

Consolidation now gathers prior heads through `claims_for_subject` and `claim_consolidatable`, includes their values in the merge request, and partitions by `(subject,predicate,world,facet,topic_key)`. Multiple prior heads participate in detection, but only a unique head can be superseded. Escalation retains the gap obligation and also emits `core.conflict.open` through the existing promotion sink at `conflict_open_marker_id`. `close_persistent_conflict` writes a stable `core.conflict.resolved` audit through the same gated writer. ARCH-0003 §G.1 explicitly says per-predicate topic-key derivation is not pinned, and an older paragraph still says the engine never detects conflicts. The later Wave contract overrides that older baseline. This implementation records the extractor-supplied `scope.topic_key` question as canonical data; it does not guess a question from natural-language answer strings. Absence retains conservative full-predicate grouping, so a missing key cannot hide a changed answer in its own answer-key bucket. Canon should document this extractor-data seam.

Source ranking uses shipped `context_pack/source_ranking.json` PACK data and an explicit builder override. Default equal multipliers clamp observed claims below their user-stated mates across predicate families. Mates include subject/predicate/world/relationship/facet/topic; world sections remain separate. This is read-time ranking only and cannot supersede a stated claim. Tests are pending.

### Canon decisions for the newly integrated modules

DAG canon: `oneiron/backend/oneiron-arch-0006a-conversations-api-core.md` and the CONV-01/02 SOW. HEAD/canonical/session sidecars stay local. Reply revision hashes the encoded TURN body; late headers append through the engine door. Legacy writes cannot add invisible bare records to an adopted DAG.

Recovery canon: `oneiron/core/oneiron-arch-0038-deletion-redaction-canonical-snapshot-v1.md`. A NOTE can have multiple heads/forks, so canonical state carries every document key, current binding and immutable landing receipts. Unknown container schemas reject rather than disappear. The recovery driver returns fresh state and restores standard materialization; the caller owns stopped-writer coordination and live-window publication. No historical redaction-sweep completion is asserted.

Ports canon: `oneiron/backend/oneiron-arch-0005a-backend-ports-integrity.md`. Transactions stay caller-owned. Adapter methods must not start or commit nested writers. Explicit conformance adapters are not proof of complete production migration; remaining direct callers are being moved separately. Existing overlay/session reads must retain their view semantics.

Streaming canon: `oneiron/core/oneiron-arch-0002-structural-entities.md`, Streaming MESSAGE write path. Receipts are written inside the existing witness transaction, after MESSAGE validation and before final actor revalidation. A refused finalize retains its buffer and commits neither MESSAGE nor receipt. Buffers never become partial CRDT ops.

The 122-test integrated scope includes LMDB and memory-adapter conformance, exact dependency deletion, clock-floor reopen, canonical carry list/blake3, fresh document reconstruction, redaction byte preservation, quarantine and typed repair pressure. It precedes the full caller-migration patches and the new originless-field/conflicting-origin guard regression.
