# Agent verb projections

`agent-verbs.json` is the shared facade/task/room verb table. `generate.py` emits the
engine dispatcher, MCP catalog, HTTP facade handlers, Rust client methods,
N-API/PyO3 methods, and TypeScript/Python namespaces. All domain behavior stays
in the engine. The facade methods use the same generated dispatch as tasks and rooms.

Run from the repository root with the pinned Rust formatter available:

```
python3 scripts/sdk/generate.py
python3 scripts/sdk/generate.py --check
python3 -m unittest discover -s scripts/tests -p test_agent_sdk.py -v
```

`--check` fails when any generated byte differs. Do not hand-edit generated
files or marked blocks. New rows supply their engine input/output types, call,
HTTP credential scope, and MCP argument fields. The optional `admission` object adds boundary
checks before actor resolution (an empty object still checks the DTO shape).
`validate` is Rust over the typed `input`, shared by embedded and remote
preflight; `unrestricted_record_scope` requires an unrestricted HTTP credential.
`proposes` marks a `Write` row whose write lands at the actor's ceiling, so under
`proposed` it waits for review: the MCP door admits it with `core:propose` (ARCH-0028
propose-only). Every other write takes effect at once and needs `core:write`.
`lands_turn` marks a `Write` row that lands a conversation turn: its generated HTTP
facade handler wakes the Dreamer's turn producer after the write (ARCH-0026 RD-26).
`refs` (OF-063) lists a row's typed record-ref slots as JSON pointers into its input,
`*` taking every item of an array (`"refs": ["/edges/*/target_ref"]`). The row's
generated engine fn calls `gate::record_references::admit_row_references` before the
engine call: every ref named there must resolve under the writer's own scoped read, or
the write is refused with `INVENTED_REFERENCE` (the field pointer, never the ref) and a
`reference_refusal` receipt is written on its own write first. Every door that reaches
the row (HTTP facade, MCP, code mode, SDK) meets the check once. Declare citation slots
only: a write's own target and create-or-get ids are the engine's own lookup, and free
text is never parsed for refs. Only a plain memory row takes `refs`.
`prose_links` (OF-063 prose links: Engine ruling 10-17) lists a row's text slots, read for
Markdown links `[label](oneiron://<ref>)` (code spans, fences, indented code and raw HTML
skipped, bounded in count and length) by `gate::record_references::admit_prose_links` before
the engine call. A
pointer may end at an opaque value, whose every string is read, and `*[key=value]` takes
only the array items whose `key` is that string, which declares them AI-written (otherwise
the writer's class decides). An AI-written link that does not resolve for its writer never
refuses or rewrites the text: it writes the same `reference_refusal` receipt with outcome
`unlinked`, before the engine call (an attempt receipt), and none inside an anonymous
off-record session. Witnessed turns (`vault.witness`, `vault.rooms.speak` and every other
witness door) declare no `prose_links`: the witness program reads each companion message
once itself. Readers turn text into typed spans with `vault.refs.links`, each link resolved
under their own read through `vault.refs.resolve`; one they cannot read is its plain label.
Prose links are display only and never feed a grant, scope or authority path.
`vault.witness` and `vault.claims.upsert` retain their size checks. `vault.recall`
and `vault.receipts` need the scope restriction as well as query/limit validation. Their shared SDK
request DTOs preserve the wire defaults. Language-specific DTO conversion stays
in generator templates; only manifest rows select which methods are emitted. Language DTO declarations live in the generator;
keep them aligned with the serde domain types when a domain shape changes.

`mcp` selects `tool-first` or `none` for each SDK row. For projected rows,
`mcp_fields` maps each MCP argument to a field path in the typed engine input.
`$` decodes the whole input from that argument. `=field` requires an envelope
argument to equal that field on the decoded input. Required arguments default
to all mapped fields; `mcp_required_fields` can narrow that set. The generated
MCP dispatcher calls the same typed SDK functions as the other transports and
serializes their outputs without adding a per-verb result shape.

`context` defaults to `memory`. `context: "board"` selects the existing
`BoardVerbContext` instead: its call runs over the gateway's credential-bound
snapshot and STREAM registry. These rows expose typed context-taking engine
functions and MCP tools, not Memory-only HTTP/remote/language methods that
cannot carry that host state. `mcp_result` optionally selects a result projection
when a credential-scoped producer must report omissions (the TASKS section).

`section` selects the Context Board plugin allowlist independently of transport
registration. Board, task, room, facade, and plugin catalogs are projections,
not independently maintained name lists.

`mcp_scope` is `filtered` for row-filtered board results, `target` for an
addressed entity, and `unrestricted` for actor-wide execution. `mcp_page` can
select a continuable producer whose output is not a vector or cursor page;
otherwise continuation follows `page` or a vector output. Credential write
admission follows `scope`, not a second hand-maintained list.

Every row's `input` also selects its schemars input schema. MCP projects the
same `mcp_fields` paths into that schema, including `$` and `=field`, and keeps
the common envelope constraints. An unresolved input field refuses tool
construction instead of advertising an unconstrained argument. Domain validation
still runs at dispatch; schema derivation does not replace the gate.

A bounded output supplies `page: {"rows": "rows", "cursor": "next_after"}`.
The cursor's presence, not a full row count, decides source exhaustion. A vector
output is an exhaustive set. MCP can split either result into retained transport
pages; drain `meta.page.cursor` before using an engine `next_after` cursor.

## Task handles

`client.ask(spec)` returns `{handle, count, replayed}` immediately. The
caller can keep working. `client.wait(handle, stepKey)` returns `Pending`,
`Ready`, or `AlreadyResumed`; it does not block the OS thread, suspend the run, or
poll the server. Re-enter the same durable step with the same key. Different
calling steps use different keys. The first ready delivery consumes that step's
C9 signal exactly once; replay reports `AlreadyResumed` with the same answer.

Only the admitted holders may call `tasks.answer(handle, resultRef)`. The first
answer wins. Later holders receive that same winner. Optional `outcome_binding`
uses the shared versioned question/outcome model. `tasks.outcomes(handle)` is an
owner-only read of currently eligible calibration pairs, not an unrestricted
fact export. An answer supplies a real result reference; the adapter never
invents a model prediction or confidence receipt.

HTTP uses `/v1/core/facade/<verb>`, the verb's full dotted name
(`/v1/core/facade/vault.claims.upsert`), with the existing credential binding. Core
SDK task and room requests cannot choose another authenticated actor. MCP uses
the same dispatcher after its family admission. Private N-API method names are
camelCase; PyO3 method names are snake_case. The public tree puts `ask` and
`wait` on the handle, `tasks.answer/outcomes` under `tasks`, and
`vault.rooms.list/messages/claim/speak` under `vault`.

## Real native boundary check

Build the addon and run this on the host that owns the Cargo artifact:

```
cargo build -p oneiron-napi
node scripts/tests/test_native_agent_verbs.mjs target/debug/liboneiron_napi.so
```

On macOS, use `target/debug/liboneiron_napi.dylib` instead. The script loads the
real library in Node. It opens an isolated vault and exercises both wait orders,
exactly-once resume, first-answer replay, shared outcome labels and room listing.
It needs no package installation or mock native module. This is distinct from
the projection fixtures above. The crate's own Rust tests need no Node host on
macOS or Linux: macOS links them with dynamic symbol lookup, and on Linux the
`dyn-symbols` feature of napi's test-only dependency loads the Node-API symbols
dynamically. Those tests cover conversions and engine calls; the real Node-host
boundary is covered by this script and `crates/oneiron-napi/tests/node_host.cjs`.

## Code-mode declarations

`crates/oneiron/src/task_verb/code-mode.d.ts` is the verb table as code mode
declares it: one signature per row at its full path (`vault.recall`,
`self.focus.refresh`, a bare `describe`), which the engine
renders from each row's compiled input schema (`code_mode_declarations`). The
executor prompt and shadow mode's type check read that rendering. This script
cannot see the schemas, so `--check` only requires the file to declare exactly
the table's rows; the engine test `code_mode_declarations_file_is_the_verb_table`
requires it byte for byte. Regenerate it after a table edit with:

```
ONEIRON_UPDATE_TEST_FIXTURES=1 cargo test -p oneiron --lib code_mode_declarations_file_is_the_verb_table
```
