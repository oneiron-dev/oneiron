# Agent verb projections

`agent-verbs.json` is the shared facade/task/room verb table. `generate.py` emits the
engine dispatcher, MCP catalog, HTTP facade handlers, Rust client methods,
N-API/PyO3 methods, and TypeScript/Python namespaces. All domain behavior stays
in the engine. The facade methods use the same generated dispatch as tasks and rooms.

Run from the repository root with the pinned Rust formatter available:

```
python3 scripts/sdk/generate.py
python3 scripts/sdk/generate.py --check
python3 -m unittest discover -s scripts/tests -p test_agent_sdk.py -v
bun test packages/oneiron/test/agent-verbs.test.ts
```

CI checks exact generated bytes. Do not hand-edit generated files or marked
blocks. New rows supply their engine input/output types, call, HTTP credential
scope, and MCP argument fields. The optional `admission` object adds boundary
checks before actor resolution (an empty object still checks the DTO shape).
`validate` is Rust over the typed `input`, shared by embedded and remote
preflight; `unrestricted_record_scope` requires an unrestricted HTTP credential.
`witness` and `claim_upsert` retain their size checks. `recall` and `receipts`
need the scope restriction as well as query/limit validation. Their shared SDK
request DTOs preserve the wire defaults. Language-specific DTO conversion stays
in generator templates; only manifest rows select which methods are emitted. Language DTO declarations live in the generator;
keep them aligned with the serde domain types when a domain shape changes.

`mcp` selects `tool-first` or `none` for each SDK row. For projected rows,
`mcp_fields` maps each MCP argument to a field path in the typed engine input.
`$` decodes the whole input from that argument. `=field` requires an envelope
argument to equal that field on the decoded input. Required arguments default
to all mapped fields; `mcp_required_fields` can narrow that set. The generated
MCP dispatcher calls the same typed SDK functions as the other transports and
serializes their outputs without adding a per-verb result shape.

A bounded output supplies `page: {"rows": "rows", "cursor": "next_after"}`.
The cursor's presence, not a full row count, decides source exhaustion. A vector
output is an exhaustive set. MCP can split either result into retained transport
pages; drain `meta.page.cursor` before using an engine `next_after` cursor.

## Task handles

`client.tasks.ask(spec)` returns `{handle, count, replayed}` immediately. The
caller can keep working. `client.tasks.wait(handle, stepKey)` returns `Pending`,
`Ready`, or `AlreadyResumed`; it does not block the OS thread, suspend the run, or
poll the server. Re-enter the same durable step with the same key. Different
calling steps use different keys. The first ready delivery consumes that step's
C9 signal exactly once; replay reports `AlreadyResumed` with the same answer.

Only the admitted holders may call `tasks.answer(handle, resultRef)`. The first
answer wins. Later holders receive that same winner. Optional `outcome_binding`
uses the shared versioned question/outcome model. `tasks.outcomes(handle)` is an
owner-only read of currently eligible calibration pairs, not an unrestricted
fact export. An answer supplies a real result reference; the adapter never
invents a model prediction or confidence receipt.

HTTP uses `/v1/core/facade/<verb>` with the existing credential binding. Core
SDK task and room requests cannot choose another authenticated actor. MCP uses
the same dispatcher after its family admission. Private N-API method names are
camelCase; PyO3 method names are snake_case. The public namespaces keep
`tasks.ask/wait/answer/outcomes` and `rooms.list/messages/claim/speak`.

## Real native boundary check

Build the addon and run this on the host that owns the Cargo artifact:

```
cargo build -p oneiron-napi
node scripts/tests/test_native_agent_verbs.mjs target/debug/liboneiron_napi.so
```

On macOS, use `target/debug/liboneiron_napi.dylib` instead. The script loads the
real library in Node. It opens an isolated vault and exercises both wait orders,
exactly-once resume, first-answer replay, shared outcome labels and room listing.
It needs no package installation or mock native module. This is distinct from
the projection fixtures above. The standalone N-API Rust test binary still needs
macOS; on Linux its Node symbols are supplied only by a real Node host (ONE-1997).
