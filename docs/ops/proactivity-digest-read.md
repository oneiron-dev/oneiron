# Read a delivered proactivity digest

The canonical served verb is `vault.proactivity.digest.get`. Pass
`{"id":"<64-hex locator>"}` using the value in a `dreamer.digest` inbox
notification's `source.result`. The SDK, facade and MCP expose the same door.
It needs read scope over the whole vault and the existing live owner proof.
Embedded-only handles receive the ordinary host-only refusal and served-client
hint. The existing owner HTTP read remains available.

The answer is the existing `ProactivityDigestView`, or `null` if no digest has
that locator. The locator identifies the stored digest, not the content hash of
the viewer's reply. The native reader verifies the canonical stored digest and
keeps its existing per-owner private-source screening and text rebuilding.

This is owner-grade catalog reachability. It adds no non-owner Agent-class
permission and does not fabricate an owner proof from an agent or holder. It
does not narrow the existing any-owner read behavior, change digest recipients,
or add count-only disclosures, new field projections or read grants. A real
non-owner agent read and its authority coverage remain separate work.
