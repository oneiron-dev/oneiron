# Decision generation allowances and receipts

A decision clock and a generation allowance are separate controls. `Deadline` means the
call ran out of work time, its answer arrived too late, or the caller took the answer
early. `GenerationAllowance` means the caller allowed no further logical generation to
start. It does not mean a timeout, a provider failure, or a measured token total.
`CaptureUnsupported` means no remaining provider can complete the requested captured
read. It does not turn the ordinary provider interface into a fallback.

The ladder keeps the same prior-answer rule for each cut. A reversible read may keep
its last eligible answer. A read with no answer, an abstained or in-band prior, or an
outbound effect cannot use that prior at the cut. Its receipt and any person ask name
the actual stop cause. A cut rung never becomes the source of an earlier answer.

The captured-provider interface keeps unsupported reads separate from unstarted reads.
An unsupported `None` returns before that provider reads or sends; it never permits a
retry through the ordinary interface. A supported read keeps its original provider
error and every native settlement in its paid prefix. `NotStarted` is not an abstention,
a negative answer, or a zero person probability. In a sequential pack, it retains its
question ordinal and leaves later questions unstarted. `Stopped` means the native
read began but the allowance stopped it before a complete result; its settlements
remain available without presenting it as an unstarted read or a terminal answer.

Captured offline, standing host, attribution, and placement rule reads use their original
single and pack methods. They start no model generation and consume no generation allowance;
their settlement inventories are empty because those native methods admit and send nothing,
not because absence proves no work. Attribution still filters its prepared facts against the
question's options. Placement still uses its already-prepared tree reading; capture does not
read a new tree or turn that reading into authority.

The native captured-request adapter keeps the ordinary singleton, packed, and
person-appended request shapes. It transfers settlements before it checks the provider
result, arity, or answers. A fully answered request uses the original person join and
answer-clock handling. A mixed request keeps unstarted question ordinals unpinned; an
answered target whose person question did not start stays an incomplete logical read,
not an answer with a made-up person probability. A late answered target keeps only its
attempted provider pin.

The optional captured ladder uses that adapter at each native request boundary. A
whole unstarted chunk may skip an unsupported provider without splitting the native
pack into probes. Each question keeps the rung that served its chunk. A tournament
that already answered a chunk keeps its attempted pins and settlements if a later
chunk cannot start; its incomplete outer winner is not an answer. Unsupported
step-ups try the remaining configured takers, then use the same eligible-prior cut
rule. They never enter the unavailable-provider branch that discards that prior.

The allowance is a granted start slot, not proof of provider bytes or token use. A
native admission after that slot may still fail. Memo recovery starts no generation;
a schema correction uses a new logical generation, while a transport retry reuses the
same one. Receipt counts and successful-response counts do not establish that boundary.

The optional durable port checks a caller's logical-generation admission only after
memo recovery and the native request and schema preflights. Each schema correction
checks it again, while transport retries reuse that attempt's lease and logical
start. A denied first start returns a typed cut without usage. A denied correction
keeps the actual answered, settled prefix, including an actual zero report; it
never turns that prefix into a provider error, a fallback, or a memoized answer.
Lease-admitted observations and request captures remain separate from provider
bytes and logical-generation admission.

The optional scoped generated entry carries that same context through the first
generation and the native captured stronger-provider close. Finished generated steps
stay in the caller's spend inventory. A paid correction prefix cut before a terminal
step stays in its separate usage inventory; it has no terminal memo and must not pin
a checkpoint-paid step hash. Native stronger-provider settlements stay in the
caller's receipt inventory even on a later error. Neither inventory alone proves
complete usage.

The Arc's existing generated-only advisory path borrows its actual start counter for
this admission. It keeps the same allowance and the same reserved narrative slot.
Memo recovery runs before a new start can be denied. Each schema correction takes a
new start, while transport retries share their start. There is no outer pace shortcut
that skips a memo, and no second counter update after the response. This does not
enable stronger reads.

System One supports native captured reads outside the purposes admitted as extraction.
Its sequential pack checks the allowance after each question's capability,
remote-posture and key preflights, before binding that question's run. A preflight
abstention starts no generation. A denied generation leaves its ordinal and later
questions unstarted; a later provider error still keeps the settled prefix. A
granted start slot is not proof that the subsequent native admission or send succeeds.

The house reader supports native settlement capture. A request carrying a generation
admission requires the reader's native generation port; a reader without that port
returns unsupported before capture or a paid gate. The first allowance follows the
existing question and shape checks, before the gate admits or dispatches a permit.
The native reader checks each missing-label full-vocabulary generation separately;
a packed request or settlement is not a generation count. Tokenization, worker waits
and transport retries do not take another generation slot.
A denied first allowance starts no read or permit. A denied later allowance returns
a stopped paid prefix, not `NotStarted` or a complete decision pack. That prefix keeps
usage from every initial batch reply and each completed retry, including questions
not yet processed when the allowance stopped. The same gate settles it once against
the same borrowed lease. It creates no terminal decision, memo or checkpoint step hash.
The original ordinary packed request, paired and person readouts, clocks and error
settlements remain unchanged. Caller-run handles bind to the capture inside its scope;
funded handles are created inside that scope. Capture never settles the permit again.

A nonlocal extraction needs its actual request's native extraction admission too.
The nonlocal house reader does not yet supply that request through the captured
interface, so that context returns unsupported before any capture, read or send.
A System One rung without an explicit catalog binding likewise returns unsupported
before any capture; with one it prepares its actual transformed native request
before paid admission, admits its content-complete view, and sends those same owned
body bytes on the original seat afterward, with the caller's current work time and
physical credential release. The existing admitted-purpose normalization also treats
both autonomy purposes as extraction. The on-device house reader can capture with its
native generation port or without a generation admission. A run's credential check is
not the host's extraction predicate. The captured context also borrows the original
request's complete scope; evidence identifiers do not recreate that scope.
Preparing native bytes or naming a catalog model does not itself authorize egress.
These remain scoped request adapters, not new egress policies or
ordinary-call refusals. None of these providers' capture support enables the excluded
stronger Arc path.

Configured local vision also supports captured decisions. Its actual fitted images,
question, state and answer schema pass through the existing role admission once,
with the original complete scope, purpose and host extraction predicate. That
admission precedes the generation allowance and the original paid send. A call
without images still abstains unspent. Each question that does send uses one
logical generation slot; a denied allowance returns `NotStarted` without a model
call. The same sourced run, role route, work deadline and credential guard send the
admitted request. Capture collects the original settlements without settling them
again. Ordinary requests and private terminal-record behavior remain unchanged.

Settlement inventories also do not establish complete token measurement. Missing usage
stays unknown; billed reservations and currency charges are not actual token counts.
Reading a settlement never authorizes settling the model permit a second time.

Native settlements also keep `native_quantity`, the pricing quantity in the call's
own typed unit before host rate conversion. Its wide `units` value is a decimal
string on the wire. A dispatched call with no reported usage carries its native
reservation there; an unstarted or kept call carries its actual zero for this
settlement. This does not turn the quantity into measured tokens or charge it again.
The original run-line charge, allocation, errors and reported usage stay separate.
The server log keeps the decimal quantity and the same sanitized unit-name format.
This field supplies native accounting data; it does not enable any provider.

The Arc tallies each captured token-native quantity once in its existing wake
budget. It does so before processing generated-step usage and terminal receipts,
so a failed durable-receipt lookup or a later park keeps the native settled prefix.
Generated terminal usage, an unfinished generated correction's usage, and native
stronger-provider settlements are separate inventories. The tally never adds a
receipt's converted line charge or failed-rung count on top of its native quantity,
and never settles the model permit again. A reservation-known quantity still does
not make missing actual token measurements known. Non-token quantities are not
converted into the wake's token domain; they remain in the native receipt inventory
and raise a warning. This is a token-native accounting connection, not complete
provider coverage or permission to enable stronger reads.

The Arc stronger-read path remains excluded by `generated_only`. The typed captured
outcomes, native common path, and truthful stop vocabulary do not enable it by
themselves. Provider coverage, memo-aware correction pacing, and the accounting join
must be complete first.
