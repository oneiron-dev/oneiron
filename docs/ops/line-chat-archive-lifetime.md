# LINE chat observation archive lifetime

LINE provider ingestion records a private capture of the exact native archive
version returned by the provider-event writer. The capture binds the artifact,
version, content hash and version claim. Only a native join capture owns that
version. A text observation borrows its message archive.

Deleting a bot/chat ChannelIdentity selects its observations through the stored
route and live address fact. Erasing the provider MACHINE or source artifact
also selects provider observations before its source graph goes. Public archive
references may select observation records, but never establish archive-byte
ownership. A record-only observation has the same durable held continuation as
a captured observation, without a version or body inventory.

The native provenance writer detaches the capture. An owned join releases only
its exact version after other captures, public observations, step pins and legal
holds let it go. An accepted erase of the actual source artifact may release
that artifact's version; identity and MACHINE ids remain receipt attribution,
not authority to erase a borrowed text archive. Full artifact cleanup preserves
only the accepted exact versions that are still pending.

Pending source selections and version releases live outside CONTENT checkpoints.
A hold keeps an observation whole while its source erase goes on. The legal-hold
settlement pass retries these selections, and erase completion remains pending
while the accepted source still owes native record or custody work, including
after the last hold row has gone.

Before a version releases references, its erase captures the original governed
body instances with their digest bindings and original inline ASSET instances.
After an older CONTENT restore omits version or binding rows, retirement uses
only those saved original instance addresses. It does not resolve the old hash
or ASSET key into a later upload's instance. Existing native erase notes,
last-holder debt, retirement intents and custody completion checks decide when
the erase is complete. Already-retired originals are noted without re-creating
a retirement intent. Released versions never expand their captured inventory.

Checkpoint landing and custody activation prune only CONTENT captures whose
claim or exact version no longer stands, or whose accepted release detached it.
They preserve LIVE obligations. Mere metadata absence is not proof that an
instance key retired. Ordinary deletes keep the native restore window; erases
retire or owe the original instances through native custody.
