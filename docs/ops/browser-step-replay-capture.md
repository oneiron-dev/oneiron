# Browser handoff step replay capture

A leased canonical executor step may carry a browser planner's pending
`NeedsAgent` evidence. The backend appends that host data after the
executor stages its request. Before sending the admitted call, the host
refreshes that same staged capsule with the entire post-route request.
The original message prefix, typed executor run and vault identify the
staged key; matching that prefix alone does not stand in for storing the
actual request.

The refreshed request passes through the existing side-row admission wall
and spill path. Its admitted body, native exposure spans and capsule row
commit together. The new request uses a separate immutable body occurrence;
only the capsule's prior request occurrence and its own marks are released.
A superseded inline body is deleted in that same transaction when no other
descriptor or standalone raw-output hold retains it. An unheld file uses the
existing collector queue. The step's original start, actor, lease and other
holders stay in place.
Unknown browser evidence does not gain a fabricated source-row witness.

An erased, withdrawn, finalized, stale or missing capture is not revived.
A withheld request stays typed and stores no raw copy. A storage failure
never fails or delays admission of the live call; it leaves the rewritten
call without a replayable capsule rather than certifying the old request.
The awaiting capture takes the new matching digest only after the native
writer commits, so the answering rung and route pin bind to the actual
post-route messages.

When the admitting-role capture is present, its prefix role note runs
before this refresh. The refresh preserves that role without guessing one.
Saved-workflow owned handles, strict replay, browser evidence, model
admission and handoff acknowledgement keep their existing behavior.

This is the browser-request rewrite slice of FIX 3613, not a claim that all
capture sources are known or all replay paths are complete. An ordinary
matching engine/server rollout is sufficient. No protocol, SDK verb,
configuration, migration or guest artifact changes are required.
