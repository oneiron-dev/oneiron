# Native decision-read evidence

A House decision read can retain its native request and response observations on
its original admitted call. A logical read can fail after the provider returned
complete token counters. The original error and the original permit settlement
still stand.

## Failed-read totals

The optional House model-call observer can include input and output totals for a
failed read when its actual gate supplied the original admission and the same
retained call has a known immutable invoice. The reader checks that call's vault
boot, budget line and lease. It does not reconstruct a call from a run instance,
model-call index, request digest or matching scalar quantity.

Every recorded completion request must have a parsed successful response, exactly
its native prompt population, distinct in-range prompt indices, and both native
token counters. Arithmetic must not overflow. The totals must agree with that
original call's retained invoice. The output total keeps the existing House
one-position forward-pass accounting floor, including when a raw output counter
is zero. The raw observations keep the reported zero unchanged.

An absent invoice, an unresolved request, a partial response or missing counters
leaves usage unknown. A known prefix is not a complete failed-read total. A source
read error also leaves the observer's usage absent; it never replaces the
original decision error or changes the returned answer.

## Limits

These are response-reported input and output totals under the existing House
accounting policy. They do not reconstruct cache counters, text or reasoning
breakdowns, timings or inference receipts. The usage object's default detail
fields are not measurements of those missing details and must not be used to
establish a cache-aware price.

The observer still applies the existing no-record checks and stores only the
content-free failure class, never the error text. A successful or malformed
returned response keeps its original usage path.

This evidence does not authorize work, charge a budget, acknowledge payment,
change NET or GROSS coverage, or enable stronger-rung Arc openings. It does not
prove unreported remote expense or that a constructed request reached a model.

## Arc opening step accounting

An opening's generated response carries its producer's optional terminal
`StepReceipt`. The attempt tally uses that exact receipt to check whether the
step is already paid. A memoized response is not automatically a paid response.
A request hash or attempt id does not replace a terminal receipt.

A generation without a terminal receipt keeps its reported usage without
inventing a step binding. If the paid-receipt lookup fails, the opening parks
with the remaining non-memoized generation usage, as the other scoped decision
consumers do. A backend-touch flag does not decide what is paid.

Native settlement pricing quantities still follow their existing GROSS tally
path, including receipts without a native admission. They do not gain NET
pairing or an extra invoice charge from this step accounting. Staffed stronger
providers remain excluded from Arc openings until their per-read cost and
freshness contract is complete.

## SystemOne native-source attachment

A captured SystemOne pack or single read can carry the actual paid permit's
original native admission on its runtime settlement copy. The caller's existing
capture behavior stays in place. An own-meter read enables capture only when
its context supplies an original native source. Binding failure warns and keeps
the ordinary read, deadline and settlement paths.

This attachment alone does not retain a native input or response invoice. An invoice
lookup may still be unknown. The binding does not change the permit's pricing
quantity, settle it again, or authorize a payment. Existing captured-receipt
consumers keep their own accounting paths. Staffed stronger providers remain
excluded from Arc openings. Ordinary host receipt sinks do not receive the
runtime admission attachment.

## SystemOne original response quantities

A SystemOne read with that original admission retains its finalized native input
body hash before the prepared request is sent. The hash describes input bytes;
it is not a terminal claim, proof of send or a payment identity. Failed evidence
writes warn and keep the ordinary request and settlement paths.

A successfully parsed single or pack response retains its reported aggregate
input and output counters with its immutable invoice in the same writer. A pack
has one aggregate measurement, never a measured share for each answer. Raw output
zero stays zero; House's forward-pass floor is not applied to SystemOne. A failed
or cancelled request does not turn a known prefix, reservation or absent counter
into a terminal invoice. A successful response does not prove the expense of
unreported retries or other remote work.

The original-admission terminal-usage reader accepts these SystemOne source
counters and checks their sum against that same call's invoice, boot, line and
lease. House reads still require their complete native prompt population. The
SystemOne model-call observer uses that reader for a failed read and keeps usage
absent if its source is unknown or cannot be read. Successful returned usage and
all existing no-record checks stay unchanged. Default detail fields are not
measurements of cache, timing, price or inference receipts.

This is source and observer plumbing only. The original settlement still owns
its pricing quantity. Nothing here pays the invoice, substitutes NET for GROSS,
changes coverage or enables staffed stronger-rung Arc openings.
