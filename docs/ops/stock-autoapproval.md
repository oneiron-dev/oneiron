# Saved-policy stock offers

Stock autoapproval uses the owner's persisted `StockAutoapprovePolicy`. Its
existing default is OFF. A changed setting has a native policy revision. An
automatic answer records `StockPolicy { revision }`, not a person's authentication.
The committing writer reads that live revision again; an earlier ON read is never
an authorization. Manual answers and training handoffs use their original paths.

The trusted Coach host attempts pending offers and newly recorded offers. It makes
no model call, starts no worker, downloads no file and grants no run permission.
Only a pending STOCK offer with its exact digest can qualify. The core writer
reuses the original candidate/registry/manifest validation, original stock switch,
answer table, ask closure and applied notice. The old binding stays available to
the original authenticated-owner undo. Promise checks remain scheduled as before.
TRAIN never uses this path.

## Current quality

The native Final paired measurement must still be the immutable offer's source.
Its card must approve. The current cohort, membership, rubric, scorer, method,
axis, seat canary and floor settings must match in the committing snapshot.
The actual scoring-label fingerprint is recorded from the released task fed to
all three legs, then compared with the live case's anchoring labels. This copies
no label text into the measurement. Missing fingerprints or changed labels make
this comparison unknown; they never restrict a manual answer or add a sufficiency
metric. All required member cases must still be present.

Both current constructed offers must match the request and every measured
incumbent/candidate/retest leg. A registry model name, request snapshot alone,
backend presence or a historical card alone is not that evidence. This build's
seat canary inventory remains empty, and the existing measurement finisher still
records `NoCanary`. This change does not invent a canary or bypass that unknown.

## Native monetary comparison

Admission and current-binding evidence share ONE quote resolver. It keeps the
original custom-customer-key endpoint rule, then exact-offer host override, then
catalog projection. The original native snapshot digest, currency, all four input,
output and cache rates, and source-row semantics remain. Paid connectors, missing
rows and failed reads retain their original unknown behavior. Admission drops the
override read lock before a catalog read and freezes the original quote on the
call; settlement, ledger arithmetic and account binding do not change.

The stock decision holds an immutable read of the meter's existing override map
through its core commit. Its catalog projections use the actual registry rows
from that core transaction and open no second reader. A concurrent override edit
cannot change one side between the two quotes or before the answer commits.
Both quotes must match every measured physical-call monetary snapshot, including
binding fingerprint, currency, snapshot id and all four rates. Lease `UnitRate`
values are not monetary prices.

The existing dated seat workload is read once and checked against the offer's
frozen receipt list, counts and complete metering period. Both prices project that
SAME work, retaining the native cache split. The candidate's quantities use both
models' measured tokenizer ratios; nonidentical ratios round upward throughout.
This is a fixed-passage tokenizer projection, not a guarantee of future usage or
payment. The original integer `UsageCostInput`/`Money` owns the price arithmetic.
Historical invoice sums do not price either side. Nonfree comparisons name the
same currency; only the meter's explicit all-zero free-in-any-currency case is
currency-independent. Missing rates, unquoted cache dimensions, unknown ratios,
overflow or a more expensive candidate leave the ordinary offer unanswered.

## Files and delivery

The host reconstructs the captured managed worker's exact file/licence card.
Positive current verification of that same model and manifest needs no card read.
Otherwise the existing inbox must record that exact card Seen/Acked by a current
Owner, read in the same core decision snapshot. Publishing or listing never marks
it Seen. Unknown file evidence stays manual. No request boolean stands for file
verification, delivery, owner permission or model readiness.

The whole source may be developed with complete pending parent branches. It is
not active on main until those actual parent heads and squash integration are
qualified and the production merge bar passes. Static formatting and source
review are not a compiler, runtime, payment or whole-feature certificate.
