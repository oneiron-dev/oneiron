# Packet D — HTTP server and Node host boundaries

**Status:** proposed adversarial probes, no new verified defect. Bound: one HTTP auth/routing matrix and one Node-host concurrency matrix. Baseline `e17eeb2b`.

Canon: `CLAUDE.md` consumer/host boundary; generated `oneiron/backend/oneiron-arch-0005a-backend-ports-integrity.md` (write/read ports) and `oneiron/identity.md` (authority). This packet covers actual auth and reentrancy, not only JSON decoding. A September Wave 8 surfaces audit already proved two **different** remote/MCP defects on older main; [#984](https://github.com/oneiron-dev/oneiron/pull/984) merged their fixes. Do not count them as new ONE-1884 failures.

| Probe | Setup and attack | Observable expected result and stopping rule |
| --- | --- | --- |
| D1: HTTP auth and vault selection | Run `oneiron-server` in ordinary and managed mode with two isolated test vaults. For the same read/write endpoint, compare valid actor/slip, expired/revoked/wrong-vault authority, URL/path characters intended to select another vault, and permitted public-booking routes. Send both old `/api` and scoped facade forms. | Wrong-vault or unauthorized requests fail with typed HTTP status/body; no entity or receipt appears in the other vault. The served vault derives from its authenticated binding and boot data directory, not a request path. Trace `crates/oneiron-server/src/{auth.rs,server/vault_binding.rs,api/scoped_auth.rs,api/facade.rs,managed/vault_gates.rs}` plus handlers and their callers. One read and one write with negative controls are enough. |
| D2: Node host and single-writer | In a real Node host load the production addon, open the same vault on parallel workers and a different vault on another worker; race a read with a write, a failed/aborted write and close/reopen. Compare typed result, persisted row and process survival. | No cross-vault row or stale receipt, no unsound use-after-close, and a failed transaction never becomes visible. Trace `crates/oneiron-napi/src/{facade/bridge.rs,lib/vault.rs}` into `crates/oneiron/src/store/writer_lease.rs`; isolate a same-vault collision from a truly independent vault. Existing hostless Rust tests are **not** JS ABI proof. Stop after the one controlled concurrency matrix. |

`SyncServer` is a single `Arc<Vault>` (`oneiron-server/src/server/core.rs`); URL text is not itself a filesystem selector. `oneiron-napi` exposes host-local synchronous CRUD in addition to actor-bound facades. Do not impose HTTP tenant-bearer rules on a host that explicitly owns a raw vault handle, and do not claim async NAPI reentrancy merely from the callback surface. `auth.rs` also has explicit unauthenticated development and shared-secret modes; test the configured production posture, then verify exceptions intentionally rather than calling a documented dev mode a bypass.

Focused existing tests live in `oneiron-server/src/api/tests/`, `oneiron-server/src/managed/` and `oneiron-napi` tests. A verified JS ABI result needs a real Node process, not only `cargo test -p oneiron-napi`.
