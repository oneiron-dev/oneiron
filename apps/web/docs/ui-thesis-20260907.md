# UI thesis, 2026-09-07 — take the door, keep the instrument

The owner asked for a hard think on the UI with freedom to make drastic changes. This is
the think, then what was built from it tonight on the branch `gods-bench-20260907`.

## 1. What the app is today

The workbench is object-first. Every rail row is a thing: inbox, vault, agents, pipeline,
today, orgs, notes, briefs, tasks, threads, lenses. The agent is a configuration page.
Chat is a floating panel that rises from the agent line at the bottom of the desk.

```
 rail                 the sheet                              
 ─────                ─────────────────────────────────────  
 inbox  5             Inbox                                  
 vault                  Nightly consolidation …               
 agents                 Eiri: Hokuei outreach …               
 crm ▾   …                                                    
 office ▾ …                                                   
 channels ▾ threads                                           
 ─────────────────────────────────────────── the agent line ─
 eiri · drafting the COO intro   tory · checking filings  + new chat  ⟲
                                                    ┌──────────────┐
                                                    │ chat panel   │  400 × 600, floats up
                                                    │ (ask / run)  │  from the line's corner
                                                    └──────────────┘
```

This is good and it is ours. The inbox is the one queue. The vault shows claims with two
clocks and confidence as ink. Every send waits for a click. Grants are scoped, budgeted,
revocable, on a ledger. Nothing here should move.

What is weak: the agents page. It is a list of three rows that open a settings sheet. You
cannot talk to an agent there. You cannot see what it did for you as a conversation. A new
agent is a blank form. The panel can chat, but it is a pocket, not a room.

## 2. What the category settled this month

Two product studies landed tonight (docs/product-studies-20260907/). Grok Bot (xAI,
2026-08-11) and Squad (ex-MissionControlHQ, 2026-09-03) agree on one shape:

```
 sidebar of named teammates      →  each row opens a CONVERSATION
 group chats                     →  handoffs between agents are visible
 a Chief / Lead on top           →  the one you talk to when unsure
 "come back with finished work"  →  the promise
```

Both are chat-first and neither is chat-only. Grok Bot: form for identity, chat for the
work, routines asked for in chat and inspected in a panel. Squad: a Lead interviews you for
ten minutes and hires the roster; then a board, tickets, runs and docs take over.

They split exactly where Oneiron already stands:

| | Grok Bot | Squad | Oneiron today |
|---|---|---|---|
| consent | a sentence in the description | a ticket queue, a send-time gate | a grant with a receipt |
| finished work | in the thread | a Needs-you column, cards, receipts | the inbox |
| credentials | one computer for every bot | a browser and a vault per agent | per-identity grants on threads |
| memory | per-bot narrative | "context graph" (unspecified) | claims, provenance, two clocks |

So the instrument is not the gap. The door is.

## 3. The shift

**The agent's home becomes its conversation with you.** Not a settings page with a chat
button, and not a chat app with a settings button. One page, two layers:

```
 Agents                                            + new agent   ?
 ┌─ roster ────────┬─ the room ───────────────────────────────────┐
 │ Eiri            │ Eiri  ·  Reaches out and keeps the thread warm │
 │  drafting…      │        setup · runs · pause                     │
 │ Tory            │ ─────────────────────────────────────────────── │
 │  checking…      │  o    When is the Hokuei call?                  │
 │ Antevon         │  Eiri Thursday at 10:00. The brief is ready.    │
 │  nights         │       [ Hokuei pilot call · open brief ]        │
 │ ─────           │  Eiri Drafted the quote reply for Mika Tanaka.  │
 │ the house       │       [ waits in your inbox · open ]            │
 │  3 agents · you │  Eiri asks: reach the Hokuei COO through        │
 │                 │       Yuki's account?  allow once · + grant · deny │
 │                 │ ─────────────────────────────────────────────── │
 │                 │  Eiri ▾  message Eiri · / for commands          │
 └─────────────────┴─────────────────────────────────────────────────┘
```

Rules of the room:

1. **The thread is the default layer.** Setup (charter, channels, scopes, schedule, budget,
   voice) is one click down, in the same column, the same sheet as before. Runs (now,
   earlier today) is one click down too. Progressive disclosure, as the owner asked.
2. **Finished work is a card that points at the world.** The draft waits in the inbox; the
   card in the room says so and opens it. The claim lives in the vault; the card opens it.
   The room never carries the work itself. One place per fact stays law.
3. **A gate in the room is the same gate as in the inbox.** The consent card carries the
   inbox's own verbs (allow once, allow + grant, deny). Answering it in the room settles the
   inbox row too. Nothing new is invented; the verbs travel.
4. **The house is a room.** Antevon, Eiri and Tory in one thread with you. Handoffs show as
   lines (Antevon: "Tory, take the filings"). Reports show as cards. Antevon routes when you
   address nobody. @name addresses one agent.
5. **A new agent starts as a conversation with Antevon.** "What should this one do?" Antevon
   proposes a name and a role, then channels, then grants, then a schedule, each as a card
   you confirm or change. Each confirmed card settles into the setup layer. "Set up by
   hand" opens the sheet directly. The grant lands under your seal, not Antevon's.
6. **The panel stays.** The floating chat from the agent line is the pocket door: same
   threads, small. It gains one act, "open the room", which lands on this page with that
   agent selected. Ladder: the agent line (presence) → the panel (dock) → the room (full).
   That is the apps contract's own "one card, three presentations".
7. **Threads stays what it is.** Threads = the outside conversations (Slack, LINE, email,
   who you are on each). Agents = the inside conversations. Two doors, no overlap.

On the apps contract's rule against "a chat sidebar for the agent": the room is not a
sidebar and it does not replace the world. Replies still materialize in the world; the room
holds pointers to them. The owner's 09-07 ask reads as a re-ruling; this build honors both
readings as far as they can be honored at once. The docs page RESEARCH-0359 records the
open question for a ruling.

## 4. What else was built tonight

**Vault bulk actions.** Click selects one. Shift-click selects a range. ⌘-click toggles.
The head has a select-all. Space toggles the focused row, shift-arrows extend, esc clears.
A selection line replaces the filters row while anything is selected: the count and the
acts that apply (accept · reject · move to a world · forget · export). Acts settle in place
on every selected row and leave one receipt line. Standard table operations, nothing new.

**The selected-row chrome.** The owner called the rounded well "AI slop". Three variants
now ride the tuner (` → select chrome): `rounded` (as built), `square` (the well with no
radius), `gutter` (no fill, a hair of ink at the row's left edge, the mark the vault already
uses for the open row). He picks by feel; nothing was chosen for him.

## 5. What was not done, and why

- The rail was not changed. Core is still inbox · vault · agents. The shift lives inside a
  page, not in the map.
- No new route. The room is `/app/agents` with `?with=eiri|tory|antevon|house|new`.
- Threads was not rebuilt. It is the other door and it is coherent as it stands.
- No real backend. Every thread is a fixture; the fixtures were written to show the shape
  of a day, not to fake a product.
