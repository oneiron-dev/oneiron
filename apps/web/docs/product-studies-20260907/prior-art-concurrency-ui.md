# Prior art: how agent apps show concurrent sessions and subagents (Grok leg, 2026-09-08)

Single grok-CLI research leg (`grok --no-subagents`, first-party docs + X), not verified by a second pass. Facts only; the packet is `priorart-packet.md` in the job tmp. Read as evidence for the agents-page concurrency ruling, not as canon.


## Block 1

- **high** The agent Dashboard tab presents the current heartbeat as a Latest Run / Live Run card (not a chat thread): pulsing live indicator when running or queued, short run ID, invocation-source pill (Timer / Assignment / On-demand / Automation), relative timestamp, 2–3-line markdown excerpt, and a click-through to run detail.
  evidence: Docs: “At the top, Paperclip shows either the currently running heartbeat (with a pulsing live indicator and a soft glow) or the most recent finished one.   uncertainties:

## Block 2

- **high** On web/desktop, the thread list is grouped into pinned, active, snoozed, and settled sections: pin from a thread’s menu; drag between sections (Pin/Unpin/Settle/Un-settle/Wake); snooze cannot be a drop target because it needs a wake time; Cmd/Ctrl+Enter on a new draft starts that thread in the background and opens another draft.
  evidence: Official thread-sidebar.md: pin from the menu (settling removes the pin); drag up into pinned, onto Settled to settle, out of snoozed to wake; drop verbs Pin/Unpin/Settle/Un-settle/Wake; Cmd+Enter/Ctrl+Enter starts a new thread and immediately opens another draft (New worktree: each background submit gets its own worktree). Sidebar.logic.ts names sections pinned|active|snoozed|settled and forbids snoozed as a destination. PR #7821 (merged) adds a success toast with Open back to the background-started thread.
  source: https://github.com/pingdotgg/t3code/blob/main/docs/user/thread-sidebar.md
- **high** A sidebar thread row is a two-line inbox item: title plus status/time; Working/Monitoring (sky), Pending Approval (amber), Awaiting Input (indigo), Plan Ready (violet), or unlabeled Ready; Working/Monitoring recede (dim, lower priority) unless the row is open/selected; Working shows an elapsed timer (e.g. 8s/1m); hover actions include pin, snooze, settle.
  evidence: resolveSidebarThreadStatus / shouldRecedeSidebarThread / resolveThreadStatusPill in Sidebar.logic.ts define approval, input, working, monitoring, failed, ready and recede working/monitoring. Sidebar.tsx WorkingDuration formats elapsed time; comments say Working is static (no shimmer), dim on inactive rows, full strength when open. Bug #9214 describes rows as title + relative time + provider badge, then “Working 8s” with spinner. Theo (2026-07-23): working threads grayed out; settle sorts by settle time; merged PRs auto-settle.
  source: https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/Sidebar.logic.ts
- **high** Subagents are not nested sidebar threads: the only roster is the right-panel Agents surface (tab/card labeled Agents, shortcut A). Empty state: “No agents yet”. Live workflows are bordered sections with a phase rail and collapsible phases; direct Task/collab children are a flat “Direct spawns” list. Each agent row is a fixed three-line, non-interactive status line (title/role, activity, model · tok · tools · elapsed).
  evidence: thread-sidebar.md: “On web and desktop, use Agents to follow work delegated to subagents.” AgentsPanel.tsx: “the ONLY place the roster renders”; empty “No agents yet”; STATUS_VISUALS map pending/running/waiting→Working, idle→Idle · resumable, completed, failed, cancelled/interrupted→Stopped; AgentRow comment “Flat, non-interactive… No unfold”; Direct spawns section; workflow “{} script” and “N/M settled”; footer “● N working”, idle, settled, “Σ N tok”. RightPanelTabs: Agents card “Follow subagents and workflows.” shortcut A, liveAgentCount badge. Docs/user do not describe nested child threads in the sidebar.
  source: https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/AgentsPanel.tsx
- **high** Parallel work in a thread is native provider subagents/workflows (Claude Task, Codex collab, etc.), collapsed in chat to one spawn CTA (“Kicked off N subagents” while live, then “Ran…” / “Launched…”), with Open Agents ▸ / View ▸. Linked sibling threads via `/parallel` were proposed and not merged. A live-count badge “N agents working” sits on the right-panel toggle.
  evidence: Merged PR #5219: Agents panel is the only roster; chat gets one CTA per spawn batch; sidebar fleets read Working, watch loops Monitoring; interrupt stops every live Claude task and every live Codex child before the parent. agentSpawnSummary.ts: live lead “Kicked off N subagents”; settled “Ran…”. MessagesTimeline AgentSpawnCtaRow: Open Agents ▸ vs View ▸, Σ tokens, workflow name. PR #5745: right-panel toggle badge “N agents working”. PR #6488 (`/parallel <prompt>` linked sibling threads) is closed unmerged (merged:false). Theo 2026-08-07: “Added subagent and workflow observability, so you can see what your agents spawn.”
  source: https://github.com/pingdotgg/t3code/pull/5219
- **high** A user stops a fleet from the parent thread, not per Agents-panel row: the composer’s Stop generation control (filled square) calls interrupt, which #5219 specifies stops all live Claude tasks and interrupts all live Codex child turns before the parent. Agents rows have no stop/steer buttons.
  evidence: ComposerPrimaryActions.tsx: Stop generation button with aria-label “Stop generation” calling onInterrupt; while running, Stop is shown, and on mobile showSendWhileRunning keeps Send so a running turn can still be steered. PR #5219: “Stop only killed the parent turn while the fleet kept burning tokens” → “Stop-everything: interrupt stops every live Claude task (Query.stopTask) and interrupts every live Codex child turn before the parent turn”; also a chat liveness banner with Stop. Subagents stay in the Agents roster rather than independent nested sidebar threads (issue #538 asked for nested Codex subthreads; that nested-sidebar UX is not what main’s Agents panel implements).

## Block 3

- **high** Cursor’s Agents Window lists parallel sessions in a sidebar grouped under Workspaces (folder rows), with each chat row showing a document icon, title, optional pin star, optional green PR/branch glyph, and relative age (e.g. 2d/6d); the header funnel menu offers Grouping, Ordering, Show plus Status/PR/Environment/Source/Archived filters, and hovering a row reveals Unarchive plus a tooltip with repo and local path.
  evidence: Staff screenshots on that thread show a Workspaces list (helloworldtest folder; chats such as “Basic plan implementation”) with age labels, a pin star, a circular Unarchive control, and a Customize Sidebar menu listing Grouping=Workspace, Ordering=Updated, and filters Status, PR, Environment, Source, Archived. Hover tooltip: title, git repo path, and ~/workspace/… folder.
  source: https://forum.cursor.com/t/archive-all-caused-all-agent-chats-to-disappear-from-the-agents-sidebar/167312
- **high** Cursor presents many agents at once as tiled conversation panes (not a kanban): you split the Agents Window, drag agents into tiles, expand a pane to focus, use keybindings, and the layout persists; Agent Tabs in the editor also show multiple chats side-by-side or in a grid.
  evidence: Cursor 3.1 changelog: “Split your current view into panes to run and manage several agents in parallel… Expand panes to focus on a conversation, drag agents into tiles, and use keybindings… Your setup also persists across sessions.” Cursor 3.0 changelog (inspected separately) adds Agent Tabs “side-by-side or in a grid.”
  source: https://cursor.com/changelog/3-1
- **high** Cursor subagents are nested inside a parent session rather than listed as top-level sidebar agents: /multitask and /in-cloud spawn async/cloud subagents (own VM/branch); iOS shows a subagent card you tap for the child transcript; you steer one running agent by sending a follow-up in that chat (Send now / double Enter at the next tool call, Tab to queue, Cmd+Enter to send immediately).
  evidence: Subagents docs: each subagent has its own context and returns to the parent; “Type /in-cloud and the next task you submit runs as a cloud subagent”; cloud subagents “run from the Agents Window.” Agent overview: “Type a follow-up and hit Send now, or press Enter twice… delivered at the agent’s next tool call”; “Press Tab to queue”; Cmd+Enter sends immediately. iOS docs: “send follow-ups to a running agent, and tap a subagent card to read its child transcript”; Live Activities track up to eight agents.
  source: https://cursor.com/docs/subagents
- **high** Devin Desktop’s Agent Command Center is a status Kanban of local editor sessions and cloud Devin VMs (in flight, needs attention, blocked, ready for review, finished) plus a sidebar of every workspace session you can filter, sort, and group (grouped Spaces keep a sticky header); right-click opens a context menu and double-click renames; while an agent is running that session is greyed out and read-only.
  evidence: Docs: “organized as a Kanban board grouped by status, so you can see at a glance what each agent is working on, what is blocked, and what is ready for review”; columns tell “what is in flight, what needs your attention, and what is finished”; board includes local agents and cloud Devin VMs. “The sidebar lists every session… Filter, sort, and group sessions per workspace, with grouped spaces keeping a sticky header. Right-click a session for its context menu, or double-click it to rename it.” “Sessions are locked while their agent is running: they appear greyed out and are read-only until the agent finishes.”
  source: https://docs.devin.ai/desktop/agent-command-center
- **high** Devin nests parallel work as top-level sessions inside Spaces (not as kanban sub-cards): drag one sidebar session onto another to group; Cmd/Ctrl+\ splits a pane then New Session, or Cmd/Ctrl+T opens a new session in the current Space; each session is its own Space by default. Devin Local/CLI subagents instead appear in a separate subagent panel (profile, title, status, elapsed time, tool-call count), cancelled with x, not as Agent Command Center rows.
  evidence: Spaces docs: a Space can hold “one local agent session prototyping the UI and two cloud Devin sessions”; “Drag a session into another session” in the sidebar; split with Cmd/Ctrl+\ then New Session; Cmd/Ctrl+T opens a session in the current Space. CLI/Desktop subagents docs: “The subagent panel… shows each subagent's profile, title, status, elapsed time, and tool call count”; “Open the panel and press x on a running subagent.” A Sep 2026 practitioner post asked Desktop’s sidebar to match web nested-session display.
  source: https://docs.devin.ai/desktop/spaces
- **high** To steer or stop one of many Devin sessions you select that session and act there: Add to chat (Cmd/Ctrl+L), edit a queued message, or Cmd/Ctrl+Enter to queue server-side; Side Chats (/btw) ask questions without interrupting the main run; click stop to pause/take over the IDE; a coordinator can message, sleep, or terminate child managed-Devin sessions; CLI users cancel one subagent from the panel with x (Ctrl+C/Esc for a foreground subagent) without killing siblings.
  evidence: Session tools: “Click to stop the session to take over”; “Make sure that Devin is paused before taking over the IDE”; Side chats are read-only and “You can stop a response mid-answer, and the main session keeps running.” ACC: Add to chat / Cmd+L; Devin Local queued messages are editable. Desktop Devin: Cmd/Ctrl+Enter queues on the server. Advanced capabilities: coordinator can “Message child sessions” and “Put child sessions to sleep or terminate them.” CLI subagents: cancel via panel x or Ctrl+C/Esc.
  source: https://docs.devin.ai/work-with-devin/devin-session-tools

  uncertainties:
  - Devin ACC docs describe Kanban grouping by status (in flight / needs attention / blocked / ready for review / finished) but do not name the exact column titles or kanban card fields (title, repo, agent type).
  - Official Cursor docs do not document an in-chat Stop control; staff forum replies refer to Stop and archiving a stuck Cloud Agent at cursor.com/agents, which was not verified in product docs.
  - No first-party page inspected shows Cursor subagents as nested rows in the Agents Window sidebar (they are documented as in-session / iOS cards); whether they also appear in the sidebar is unknown.

  - Cursor staff said default sidebar grouping is Repository, but the inspected staff screenshot is grouped by Workspaces; both exist as Grouping options, and the shipping default was not re-verified in docs.
  - Cognition’s Windsurf 2.0 / Devin Desktop marketing videos exist but were not visually inspected here (Vercel-blocked blog pages); YouTube transcript language (left-hand session list, drag-to-Spaces, View all sessions by status, Local vs Cloud) was not independently re-fetched from the video page.
